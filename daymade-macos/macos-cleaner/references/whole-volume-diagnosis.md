# Diagnose startup-volume storage pressure

Use this route for an explicitly authorized whole-disk inventory or a request to reconcile startup disk usage. If the request names a suspected application as well, include it in the inventory. For a named-target-only request, stay with that target. Respect exclusions even during discovery. Inspect sizes and paths first. Reading file contents, granting protected access, installing an app and deleting data have separate scope and authorization.

## Establish what the numbers answer

- Record the startup disk, backing APFS container and current data volume free space. Use `df -k /System/Volumes/Data` for the affected-volume baseline and `diskutil apfs list` to explain the container's capacity, free space and each volume's consumption. Compare like units. APFS volumes share container free space. Do not add it once for each volume.
- Keep the volume's accounting separate from the scanner's attributed file sizes. System and auxiliary volumes, snapshots, inaccessible paths, files changing during a scan and shared extents can affect the comparison. Use the evidence available on the host to explain the difference. Leave an unexplained remainder visible without assigning it to an application or claiming an exact cause.
- Separate storage pressure from workload slowness. A full volume can explain write failures or limited room for an export. A disk map ranks occupancy. To diagnose a slow workload, observe the user's actual run and collect relevant timing, I/O or memory pressure data. Report an untested cause as unknown.

## Choose one broad discovery pass

1. **GrandPerspective when available and suitable.** Reuse an installed copy or a recent scan with known scope and date. If the user requests installation, use the [official project's free SourceForge release](https://grandperspectiv.sourceforge.net/). Verify the disk image and application signature, and follow the [publisher's installation instructions](https://sourceforge.net/projects/grandperspectiv/files/grandperspective/). Keep Gatekeeper enabled. Use [Full Disk Access](https://grandperspectiv.sourceforge.net/HelpDocumentation/FullDiskAccess.html) only when the permission change is authorized. A missing permission leaves coverage incomplete. Continue with evidence the current access permits.
2. Use an available native UI tool to scan the writable data volume at `/System/Volumes/Data` for file attribution. Accept the startup-disk root or another scan root only when the result demonstrates equivalent, non-overlapping coverage of the data volume. Use APFS accounting for System and auxiliary volumes. For a narrower approved scope, select that exact folder. Verify the selected root, displayed size metric and completed result. Keep external, network and unrelated volumes out of scope by default. If the scan cannot honor an exclusion, use scoped CLI probes instead. Use the map to find the largest branches. [Save scan data or export text](https://grandperspectiv.sourceforge.net/HelpDocumentation/SavingViewContents.html) only if it will be used to review the result or measure change later. Scan exports can contain private names and paths. Keep them local.
3. **CLI fallback.** If native UI is unavailable, declined or inconclusive, use one shallow metadata pass such as `du -x -k -d 1 /System/Volumes/Data` within the approved scope. Use narrower approved roots if the whole data-volume path would traverse an exclusion. Record permission errors. Check high-impact hidden locations such as applicable Trash directories by size when in scope. Trash on the same volume continues to consume space. Never empty it based on the scan.
4. Reconcile the large branches against the volume baseline. Use targeted measurements to validate important branches or explain a meaningful discrepancy. Avoid a second complete traversal when the existing scan can answer the same question. If the question is what grew, use [growth attribution](growth_attribution.md) with comparable dated measurements and evidence of the writer.

## Turn the scan into decisions

Start the report with available internal space, the largest non-overlapping occupants in descending order and a short accounting of coverage gaps. In a tree, treat parent rows as subtotals. Include large protected occupants so the report still explains the disk. Give each important branch an action or a next observation that would change the decision.

Rank cleanup by defensible physical space returned, risk to current work and effort. A path size is useful for choosing where to look. It does not guarantee physical release. Keep the path size, possible action and post-action available-space measurement distinct. Focus on the largest actionable groups before isolated small files. Open another branch only when it could explain material pressure, affect a requested target or change a keep/archive/remove decision.

- **Keep current work usable.** Protect active projects, application-managed originals and their live references. For historical drafts, verify completed status and the consumer's ability to reopen the archived project with its assets. Last-modified time can shortlist candidates. It does not establish that a draft is finished or rarely used. Follow [external cold archives](external-cold-archives.md) for approved moves and verify the old entry only if it must keep working.
- **Close out old tasks at the source.** Use [task evidence closeout](task-evidence-closeout.md) for worktrees and experiment folders. Check the owning repository and published deliverables first. Retain unique local edits or evidence. Reuse the existing source, lockfile or verified retained media when retiring a disposable copy. Creating another full checkout or backup adds a new storage cost and does not establish that the old one may be removed.
- **Stop at the requested outcome.** For inventory, finish once the important branches and material coverage gaps are explained. For authorized cleanup, use the existing planning and execution gates, measure the actual change in free space and verify the protected workflow. If a large branch is unresolved, name the smallest missing check or owner decision. Do not switch to smaller targets to make the report appear complete.

Reference for volume accounting: [Apple Disk Utility on APFS volumes](https://support.apple.com/guide/disk-utility/dskua9e6a110/mac).
