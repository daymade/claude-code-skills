# Audit data and discover feedback

## Map sources to the actual journey

Select sources that can change the decision; explain consequential exclusions.

| Surface | Inspect | Decision question |
|---|---|---|
| Product/reliability | Events, accepted task outputs, errors, version/device | Where does value succeed or fail? |
| Acquisition | Search queries, referrals, campaigns, landing paths, stores | Who discovers which promise, then does what? |
| Buying/economics | Billing, refunds, cancellations, CRM, sales losses, costs | Who pays, renews or leaves, at what contribution? |
| Support | Issues, discussions, tickets, support chats | Which tasks and barriers do people describe? |
| Public discourse | Forums, social posts, video comments, tutorials, reviews | Which use cases, alternatives and complaints are visible? |
| Ecosystem | Integrations, downstream code, packages, embedded copies | Does adoption bypass the main website/install path? |
| Partner/offline | Resellers, referrals, sales/service records | Which distribution or buying steps escape analytics? |
| Missing populations | Failed installs, abandoned trials, churn, non-buyers | Whose experience is absent from active-user data? |

Inspect existing tools/connectors/exports first. Request only missing inputs that
can alter a decision; never request secrets in chat. Record retention/expiry windows
and export volatile data promptly when authorized. Do not reconstruct lost historical
series from a current snapshot.

## Search feedback as an agent

1. Verify official URLs, aliases, old names, language variants and editions.
2. Search identity with task terms and positive/negative terms: use, recommend,
   alternative, install, fail, migrate, cancel/refund. Use audience languages and
   inspect original threads plus replies.
3. Sample success, failure, casual evaluation, integration and departure where
   reachable. Record queries, dates, platforms, selection and access failures.
4. Follow original bug reports, outputs, version pins, commits and reproducible
   journeys. Try another authorized retrieval route after a failure; retain the
   gap if alternatives fail. Avoid repeating identical failed requests.
5. Preserve private records with source/date, product/version, account, task,
   stated outcome, excerpt/anchor, originating evidence family, experience type,
   established relationship and limits. Separate user explanations from observations.

Do not infer a human, independent customer or deception from style alone. Label
AI-assisted/anonymous text only as supported. Exclude explicitly synthetic ratings
from satisfaction estimates. Separate vendor claims, editorial recommendations,
integrations and completed user tasks.

Group mirrors, syndication, translations, forks and repeated complaints by origin.
Count distinct accounts/projects only when established. Do not turn hits, comments
or installations into unique customers. Use selected feedback to discover problems;
estimate prevalence only with a defined sampling frame and denominator.

## Reconcile before inference

- Bind event, publication and retrieval times separately; normalize timezone and
  inspect release/instrumentation changes.
- Check pagination, schema changes, missing intervals, duplicates, identity merges,
  internal tests, bots and automated downloads. Investigate total/row mismatches.
- Preserve endpoint/report scope. Label a top-referrer share as listed-referrer
  share; keep unattributed traffic unknown. Never sum daily distinct counts to
  obtain period-distinct users without identity-level deduplication.
- Keep surviving-star snapshots separate from historical net additions. Distinguish
  downloads, executions, people and organizations. Do not assert bots without evidence.
- Verify what users currently obtain: edition, installation, permissions, upgrade
  path and public/private availability. Historical popularity does not prove current
  deliverability, default enablement or accepted work.
- Before ranking a current defect, bind the claim to a current released artifact,
  immutable revision or direct consumer observation. A newly retrieved cached page
  can still describe an old version. Reconcile reports and closed issues with linked
  fixes and the version users receive; do not reopen completed work from old text.
- If freshness cannot be resolved, classify the next step as evidence refresh,
  not product repair. Compare its decision value with other supported actions;
  do not let a stale lead automatically occupy the top priority.

Stop collecting when remaining answers cannot change the next decision. Preserve
unsearched/inaccessible surfaces rather than concluding that no feedback exists.
