# kimi-cu macOS 桌面自动化操作法

适用：通过 kimi-cu 驱动 macOS 桌面应用。先读取当前宿主实际加载的工具合同；下列 Electron/webview 配方来自 2026-10-02 的实测，不能替代当前版本的路由、权限或效果验证。

## 动作前绑定目标与权限

由执行 agent 核对本次机器、应用、账号/工作区、窗口、目标对象和用户要求的结果，再从新观察取得节点或坐标。输入前读取目标控件当前值及相关在制状态；未观察到的保持 unknown，只暂停可能覆盖它的动作，不从“本 agent 未输入”推成空白或没有在制工作。当前工具接受 `snapshot_id`、`window_id`、`screenshot_id` 时，使用同次观察提供的值；过期、上下文变化或用户接管后重新观察，不重放旧索引。

默认选择已授权且不抢焦点的后台通道。用户已有的任务授权与宿主运行时许可分别核对：当前宿主要求 `request_foreground` 和精确 human grant 时，长期授权或一句“继续”都不自动生成该 grant。激活、前台 fallback、粘贴、启动或 `AXRaise` 按当前合同判权，不用另一工具、客户端或 agent 绕过明确拒绝。

只按回执确认归因：客户端 `decline` 只证明该次未创建许可；`cancel`、RPC 错误、缺失或畸形结果也不证明用户亲自拒绝、系统/TCC 拒绝或已有许可。没有取得当前有效许可就不执行依赖它的动作。保留被拒对象、来源与范围；一条前台路线受阻不能推出后台读取、当前合同允许的后台输入、其它已授权来源或整个业务任务都不可用。后台输入仍须绑定已授权目标、当前路由与实际效果，不能改名执行被拒的前台动作。动作获准不证明查询能跨账号/工作区覆盖目标；命中后仍核实际身份、目标对象和原任务结果，同名结果不代签身份。继续独立可执行的工作，最终结果未读到时仍记未完成。

先协调已知 agent 占用；观察到用户接管、实际竞争或状态被外部覆盖时停止输入、让出，不恢复旧焦点。缺少占用接口本身不制造新的用户确认要求；宿主的明确拒绝仍须遵守。

## 可靠性分层：先选通道再动手

将旧实测的 `set_value` → 目标应用键盘 → 点击作为候选顺序，按当前控件与工具能力选择，不当作必成功保证：

1. **`set_value`**：原生控件通常走 AXValue，Electron/web 文本可能走后台替换。先读回实际值与表单状态；遮挡下曾成功、返回 `ok:true` 或文本改变，均不保证每个组件触发 onChange 或提交成功。
2. **目标应用键盘**：核对目标窗口和控件焦点，按当前合同后台投递。AX 焦点不等于应用已在前台；焦点存在也不保证按键生效。
3. **点击**：从新快照定位目标。当前工具可能支持指定窗口和不同后台路由；不要沿用“只落 primary”或“被遮挡一定丢失”的旧结论。`ok:true` 只代表工具报告的投递结果，业务效果另行读回。

## 「控件不响应」先核对目标与投递

- 先区分拒绝、未投递、已投递但效果未知和已确认无效果，再核对目标窗口、焦点、遮挡与控件状态。不凭一次无响应判“防自动化”，也不把遮挡直接当作根因或抬窗授权。
- 区分观察字段：`focused` 描述焦点，`occluded` 描述遮挡，实际前台 owner 描述前台归属；它们互不代签。某个角标节点 `enabled:false` 不能证明整个企业或应用切换入口都禁用。
- 截图范围按当前 `get_app_state` 合同和返回窗口身份确认；画面正常不证明点击命中。需要判断窗口前后序时，可只读 Quartz `CGWindowListCopyWindowInfo(kCGWindowListOptionOnScreenOnly)` 并按 owner PID 过滤；z-order 只解释窗口顺序，不证明动作效果。
- `osascript activate` 会抬起应用，不能代选应用内目标窗口；不把它当后台恢复或绕过当前宿主判权。

## 窗口与 AX 树恢复

先按当前工具合同重新观察目标窗口；full snapshot 是否改变 primary 跟踪以当前版本为准，不把观察回执当成抬窗成功。

- 旧实测中新窗口曾成为 primary；关闭重开可能恢复 AX，但会改变窗口或任务状态。先核目标、在制工作和可恢复性，仅在本次授权覆盖且不会丢工作时采用。
- 工具支持 `perform_secondary_action` / `AXRaise` 时，仍按其当前前台许可执行；没有有效许可就不抬窗。
- `get_app_state` 只剩 menubar 时，先核窗口目录与当前状态，不直接判 app 失效。重开目标窗口曾恢复 AX；重启 app 会断开 MCP、模拟器或其它 session，不能作为默认恢复。
- System Events 的枚举与尺寸调整属于不同能力；旧实测中调整尺寸可用而窗口枚举不稳定。只在当前接口和任务授权覆盖时使用，调整后重新绑定观察。

## 表单/表格填写配方

以下是旧 Electron/webview 的可验证候选；当前页面或合同不匹配时停止套用：

- **加行按钮（“+ Add a Line”类）**：焦点在当前行 value 字段时，曾通过 Tab 到行尾 delete、再 Tab 到加行按钮、Space 激活。聚焦曾让虚拟化塌陷的按钮恢复渲染；每步读回实际焦点与行数。
- 塌陷元素（degenerate frame）的 index 点击可能被拒；可在已有授权内核对键盘焦点，或调整窗口尺寸使其进入渲染区。换方法前仍核原动作结果。
- 多行 TSV 合成粘贴曾未落入 webview 表格；逐字段 `set_value` 后读回，不据此推断当前所有粘贴或表单都不可靠。
- 弹窗滚动参数按当前 schema；报“already at end”而按钮仍塌陷时，保留该容器状态，不直接判全页到底或自动放大窗口。

## 弹窗（授权/确认）SOP

1. 通过当前窗口目录或只读 Quartz 观察定位弹窗；无名、尺寸或 layer 只能提供候选身份。
2. 重新观察该窗口，核对应用、弹窗文字和操作对象；按当前合同取得需要的许可。
3. 从该观察取得节点或坐标后执行，并读回弹窗消失及目标结果。Delete 等动作必须核对准确对象；对象不对时取消，取消本身同样受当前动作合同约束。

## 大 AX 树：落盘解析与分页过期

- 输出超限自动落盘时，先看实际结构，再用 python/jq 有界解析 `tree_text` 等返回字段，不把 limit 拉满硬读，也不把截断树当完整页面。
- 当前合同若把 AX 分页保存为固定树，使用同一 `snapshot_id` 和返回的 `next_offset` 读该树；`has_more` 只描述保存节点，不保证应用 AX 全量。保存页不会替后续动作刷新现场。
- 遇到 stale、过期或替换快照时重新捕获；需要更旧聊天内容则先按已授权方式滚动，再取新观察。旧无限流页面曾需 `disable_diff:true` 重捕获，不能把当时现象推广为所有分页都会随 DOM 变化失效。

## 投递后必须验证，再决定重试

每个关键动作后，用绑定同一目标的 AX 或真实渲染读回检查状态；有持久业务结果时再查对应文件、事件或接收端。`verify_after` 若只做 AX 后置检查，就不能证明像素变化或最终业务结果。`ok:true`、`verified:true`、焦点、截图和按钮启用分别只支持其实际检查范围；`verified:false`、`effect:unverifiable`、缺失或空验证字段保留效果未知，不能直接当“确定没写入”。

重试或换通道前，先指出新增的成功前提及其证据，例如新快照、已确认修复的连接、明确未投递后的目标修正，或当前合同接受的新许可。用户催继续、重复次数或换工具名称本身不是条件变化。已投递但效果未知时先查原动作，不重复可能已发生的发送、提交或删除；安全 unknown 不因想推进就放松。已明确拒绝的路线停止原样循环申请，按其具体恢复条件处理；可继续不依赖该路线的获准工作。

复用历史成功时，同时比较工具/版本、账号与目标身份、授权模式、窗口状态和当时实际结果。旧 CUA 的成功可以提供目标身份或结果判据，不能证明当前 Kimi 后台可执行；从当前观察重新绑定方法与动作，不重放旧坐标或索引。只有正确目标上的实际结果才能关闭本轮验收。

**可选的本地防护**：宿主已有重复动作 hook 时，核实其实际注册、当前调用封装是否进入判定及执行读回，再作为辅助提醒。源码、自测和配置存在不证明实际宿主已覆盖；本 Skill 不安装 hook，也不保证自动拦截。以上判断由执行 agent 按当前合同和读回落实，文档本身不强制执行。
