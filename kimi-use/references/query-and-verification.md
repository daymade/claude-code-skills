# 查询设计与数据核验纪律

> 本页是 kimi-use 的「另一半」：驱动决定能不能拿到数，本页决定拿到的数能不能进交付物。每条纪律后面跟着它的实测战例（已脱敏）。

## 查询 prompt 模式库

Kimi 是聊天模型驱动的插件编排器——prompt 形态直接决定输出质量。以下模式都在实测中验证过。

### 模式 1：点名数据源 + 诚实条款（基础形态，每次都写）

```
用天眼查，查 <公司全称A> 和 <公司全称B> 两家的工商股东名单、对外投资、法定代表人。
每个字段标明是天眼查返回的还是你推测的；查不到的字段写「未返回」，不要用训练知识补。
回答开头先自报：本次实际调用了哪个插件、它返回了哪些原始字段。
```

四个承重部件：

- **点名插件**：「用天眼查」「用同花顺 iFinD」——不点名时 Kimi 自己决定调不调、调哪个，你就失去了对数据来源的控制。⚠️ 但**点名 ≠ 路由**（2026-08-18 实测：点名三个金融库插件，实际被路由到了天眼查）——所以要配下一个部件。
- **自报实际调用**：要求它在回答开头自报「调用了哪个插件、返回了什么原始字段」。这一件同时抓住两种跑偏：没调插件（退回聊天行为）和调了别的插件。
- **逐字段标来源**：逼它把「数据库返回」和「模型推测」分开标注。没这句，两种值在答案里无法区分。
- **诚实条款**：「查不到就明说 / 写未返回，不要用训练知识补」。实测两次都被遵守（2026-08-18）；不写这句，它退回聊天模型的默认补全行为。⚠️ 但「没有 / 不可调 / 未覆盖」这类否定证词的效力另受模式 × 模型约束——Chat/K2.6 下的一律视为未验证（见 plugin-capabilities.md 陷阱 B）。

### 模式 2：实体锚定（防同音误写 / 多候选张冠李戴）

```
先核对公司身份：中文名、英文名、上市代码、上市日期、主营业务。
（口述/转录里可能写成 <同音别名>，请先确认实体再取数。）
```

- 给**全称或代码**，不给简称。两字简称在工商系统里常常是多候选（母体/子公司/异地主体同名），锚定字段 = 成立日期 + 法定代表人 + 注册地三项对齐。
- 语音转录来的名字先核对再查——同音错字会查出一家错误的公司，且结果看起来完全正常。
- 反向战例同样成立（2026-08-18）：一次发问用的公司名本身是错的（记错的子公司名），Kimi 模糊命中了正确主体、返回了看似完全正常的数据——错误是靠权威源复核才发现的。三项对齐防的不只是多候选，也是防自己和上游记错名字。

### 模式 3：时间口径（金融数据必写）

```
时间口径：截至 YYYY-MM-DD，明确哪些是实时盘中、哪些是已收盘/已披露。
```

不写时间口径，行情/市值类数字混着盘中快照和历史收盘给你，事后无法对账。

### 模式 4：探针（能力边界确认，见 plugin-capabilities.md 末节）

新插件/新数据类型第一次用，先跑一个「确定存在的目标 × 目标字段」的最小查询确认通道，再发真实查询。**探针是「首次」闸，不是每次闸**：同一插件同一数据类型已有本机实测结论（如天眼查查股东，2026-08-18 ✅）的直接复用结论，不重复烧探针。

## 核验纪律（每条都有代价记录）

### 1. 屏幕转录会抄错中文专名——承重的名字必须过权威源

**战例（2026-08-18）**：天眼查插件返回的 20 条股东名单，逐字段照抄落盘；后按家规换权威源（工商专用 CLI）复核，发现 **6 个合伙企业主体名被抄错**（「X 鲍」抄成「X 熊」一类的形近/音近字错），而持股比例、出资额**逐位全对**。

教训：这类错「照抄值」的纪律结构上管不到——值确实是照抄的，错的是屏幕识别这一层。只有换一个不共享屏幕通道的权威源才抓得住。

**规则**：错有两层机制，别混——**转录层错**（屏幕识别抄错形近/音近字）专吃中文专名，实测那次数字恰好逐位全对，但那是样本运气不是机制保证；**源头层错**（Kimi 自己把事实搞错，见纪律 4）专吃数值与口径。所以统一闸是：**承重的专名与承重的数值都必须复核**，只是复核各防一层：

- 专名 → 独立权威源复核：本机工商专用 CLI（如 qcc，`which qcc` 先确认在不在）→ 没有专用工具就用数据源官网人工核对 → 都没有，该字段标「未复核」，**不许进交付物**。
- 数值 → 按纪律 4 并行对账。

别从「这次数字全对」外推「数字不用复核」——下一次错的就是数字。

### 2. 「全 N 条」是截断不是全量

**战例（同日）**：屏幕显示「共 20 条股东」，照抄为「全量 20 条」；权威源复核实际返回 **50 条**——那 20 条只是前 N 名，而第 20 名之后恰好躺着几条对任务承重的投资方。

**规则**：屏幕上的一切计数写成「前 N 条（截断）」，禁写「全部/全量」。需要全量清单就换专用 API 通道，别滚屏硬抄。⚠️ 但**换到 API 通道不解除这条约束**——接口自己给的计数同样只是它索引到的数量，见下方「接口自报的计数」一条。

### 3. 一屏多实体时，先锚定分节边界再抄

**战例（同日）**：一屏里上下排着两家公司的数据块（A 的股东表、B 的对外投资表），滚动后边界模糊。用**法定代表人**这个独立字段锚定（B 块出现 B 的董事长名字）才确认 20 条对外投资挂在 B 名下，没张冠李戴。

**规则**：一次查多个实体时，每个数据块抄之前先回答「这块属于谁」——用块内的独立字段（法定代表人/成立日期/注册地）确认，不靠滚动位置记忆。

### 4. Kimi 会硬错——并行拉权威源，落盘前对账

**战例（2026-06-29）**：Kimi 给的某港股 IPO 数据里，回拨后公开发售占比写成 50%（524.9 万股）；同一任务期间并行下载的港交所配发结果公告原文是 **20%（209.95 万股）**。它对的部分（现金流、应收周转）和错的部分看起来一样可信。

**规则**：Kimi 跑的几分钟里，并行从权威源（交易所公告、招股书、官方统计）拉同一批关键数字；落盘前逐项对账，冲突以权威源为准并写明。⚠️ 这条方法有一个它盖不住的失败面：**两条通道可以一致地落在同一个不是你要的口径上**——见下方「两个通道一致」一条。

### 5. 半截结果不入库

流式输出中的表格可能缺尾行、编号断裂、分节未闭合。轮询确认任务彻底完成（见 driving-kimi-app.md §等待与轮询）再提取。提前截一份「看着差不多」的结果，坏处全部落在最难发现的地方（尾部、计数、末行）。

### 6. 原始与校正分层落盘，不静默覆盖

Kimi 原始产出存档时加警示头（已知错误逐项列出 +「不要优先引用」），校正版单独成文。静默改过的「干净版」会让下一个人无法分辨哪些值经过复核、哪些没有。

### 7. 接口自报的计数，只是它自己索引到的数量

**战例（2026-08-18）**：同一时间窗、同一口径（个股研报 × 贵州茅台）比对两条通道——恒生聚源返回 **17** 条，东方财富研报 API 返回 **10** 条并带一个 `hits: 10` 字段；**交集只有 7 条，并集 20 条**。带着确定数字 `hits` 的那条，漏掉了对方能找到的 10 篇；而**明确声明「不保证穷尽」的那条反而找得更全**。

**规则**：`hits` / 「共 N 条」/ 「全部结果」这类由接口给出的计数，是**该接口自己索引到的数量**，不是那个时间窗里客观存在的数量。覆盖类任务（研报、公告、名单、检索结果）必须**双通道取并集**；单通道的计数不能当覆盖率报。

与纪律 2 是同一条规律的两种载体：纪律 2 是**屏幕**截断（看得见），本条是**接口自己的计数字段**在骗人（看不见，更隐蔽）。所以纪律 2 给的处置「换专用 API 通道拿全量」并不自动解决本条——API 通道照样会给你一个自信的数。

### 8. 两个通道一致，只证明它们对同一口径一致

**战例（2026-08-18）**：Kimi 的两个插件（万得、恒生聚源）对贵州茅台 2025 年营业收入都给 **1688.38 亿元**（同比 -1.21%）——单位对上、数字逐位对上，看起来是一次成功的交叉印证。拿完全独立于 Kimi 的第三通道复核（东方财富研报 PDF 全文），两家券商各自独立给出 **1720.54 亿元 / 172,054 百万元**（同比 -1.20%）。**增速几乎相同、绝对值差 32.16 亿。**

增速一致而绝对值不一致 = **口径差，不是错**。恒生聚源自己的返回里写明：`财务科目名称=营业收入`、`财务科目层级=2级`、`财务科目父级名称=营业总收入`——它给的是二级科目，而券商研报摘要表用的是市场通行口径。（那 32 亿的构成需要 1 级科目明细才能核，本轮未取，所以只陈述事实、不写机制。）

**规则**：交叉验证的覆盖面 = 两条通道**共有的那个口径**，不等于那个事实。判据不是「几条通道给了同一个数」，而是「**给我数的那条通道，和会来核对这个数的人（券商 / 年报 / 市场）用的是不是同一个科目**」。

**落盘要求**：财务数值必须连**科目层级与父级科目名**一起记。恒生聚源的返回里有这两项，万得侧没有——所以万得给的那个数在这一点上**不可核**，落盘要标出来。

## 落盘格式

每次取数的结果文件，头部标三样：

```
source: kimi-app / <插件名>（经 Kimi 客户端，非 API 直连）
caliber: <时点或报告期，如「盘中快照 10:05 CST」「2025 年报」>
fetched: YYYY-MM-DD
```

正文里每个从屏幕转录的数值块，标「屏幕转录·待复核」或「已过 <权威源> 复核」。这个标记决定下游能不能直接引用它。

**单位口径要坐实，别照抄**：实测遇到过同一张表里「2320 万元 / 844.4748 / 191.497 万」三种写法混用。坐实方法 = 独立口径反推——用「某股东认缴额 ↔ 其持股比例」反推总额，再与权威源返回的注册/实缴资本对账（反推总额 ≈ 权威源实缴资本 → 单位是万元坐实）。对不上就标「单位未坐实」，不猜。

**但「单位坐实」不等于「口径坐实」**：独立口径反推只能验单位与量级，验不出你拿到的是哪一级科目——那要靠纪律 8。财务报表类数值落盘时，科目层级与父级科目名和数值本身一样是必填项；拿不到就标「口径未坐实」。
