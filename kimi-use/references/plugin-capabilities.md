## 已实测的能力边界

证据级别：L1 = 实跑观察（权威源阶梯最高级）。「模式」列给出证据采集时 Kimi 客户端所处的模式 × 模型——这是结论能否被信任的前提。

| 插件 | 结论（2026-08-18） | 依据与模式 |
|---|---|---|
| **天眼查** | ✅ **可调用，返回结构化真数据**；但字段面有边界 | L1（Chat 模式取得，注意：这是 Chat 下罕见成功例）：工商股东名单/对外投资/法定代表人逐字段标来源。同日第二轮：「投后估值」字段返回**未披露**——股东/出资类有，估值类没有 |
| **标普全球市场财智（sp_data）** | ✅ **可调用**；实测覆盖=美股上市公司 | L1（用户 K3 极致实测）：describe 成功，接口含公司信息、财务、一致预期、股东、高管、关键事件、交易记录（`sp_get_transactions_advisors`，含融资轮次与交易规模字段）。非上市公司（Figure AI）精确查返回 `EMPTY_DATA`——未覆盖，不是接口故障 |

同一插件家族的边界也**不能外推**：iFinD 能查财务报表，不代表能查研报；天眼查能查股东，不代表能查司法风险全量。每个新数据类型第一次用时，都当「未验证」对待。

另一个 2026-08-18 的实测警告：**点名插件 ≠ 实际路由到该插件**——一次点名三个金融库插件的探针，实际被路由到了天眼查。所以「确认调没调、调的是谁」不能只看你发了什么，要看它自报/工具轨迹（见 `query-and-verification.md` 模式 1 的「自报实际调用」部件）。

## 两个实测陷阱（插件层专属，叠加在 SKILL.md 的五个通用坑之上）

### 陷阱 A：同名公司假阳性（2026-08-18 用户实测）

标普插件按模糊名 "Figure" 检索，正常返回 24 条交易记录——**全部属于同名的纳斯达克上市公司 Figure Technology Solutions（FIGR，消费金融）**，与目标公司（非上市人形机器人公司 Figure AI）无关。判读方法：①公司检索先核对命中主体的行业/代码是不是目标；②精确名查返回 `EMPTY_DATA` + 模糊名查返回同名异主体记录 = 目标是「未覆盖」，不是「接口故障」（模糊名复测恰恰用来证明接口工作正常）。

### 陷阱 B：模式 × 模型决定证词效力（2026-08-18 用户实测）

K2.6 快速模型对三个已装插件给出「不在我的可用数据源列表中」的否定结论，并自报了一个只有 8 个数据源的枚举——而 K3 极致下同查询三个里有两个直接调出了接口细节（sp_data 的完整接口列表等）。**从 Kimi 拿到的任何「没有 / 不可调 / 未覆盖」，先确认它是在什么模式、什么模型下说的**；Chat/K2.6 的一律视为未验证，切 Work/Agent + K3 极致重问。

## 已知缺口：券商研报

截至 2026-08-18，**券商研报检索的已验证通道都不通**：gangtise 额度 402；Kimi 侧万得/iFinD 的证词出自 Chat 模式、效力存疑，即便属实原因也是结构性的（可调用性与 API 面，不是额度）。⚠️ 这不等于「Kimi 整体补不上研报」：财新、标普全球、恒生聚源等在 Work+K3 下的研报检索未逐个测过。要下整体结论，跑一次正确模式下的不点名追问。

Kimi 给的人工替代路径（L1 记录）：iFinD / 万得终端的「研报中心」「深度报告」板块，按行业关键词 + 日期筛。

## 探针查询怎么设计

确认「插件 X 到底能不能查 Y 类数据」的最小查询形态（**在 Work/Agent 模式 + K3 极致下发出**，否则结论无效）：

```
用<插件名>查 <一个确定存在的目标> 的 <目标字段>。
每个字段标明是数据库返回的还是你推测的；查不到的字段写「未返回」，不要用训练知识补。
回答开头先自报：本次实际调用了哪个插件、它返回了哪些原始字段。
```

- 目标选**确定存在**的（知名上市公司、真实在营企业）——探针测的是通道，不是目标存在性。
- 回答里出现「未返回/无法检索」= 通道或字段面不通（这是有价值的否定结论，**前提仍是模式×模型正确**）；出现没标来源的字段 = 它在拿训练知识补，这次结果不可用。
- 探针通过 ≠ 该类数据全通：只证明「这个字段面」可调。
