## 已实测的能力边界

证据级别：L1 = 实跑观察（权威源阶梯最高级）。

| 插件 | 结论（2026-08-18） | 依据 |
|---|---|---|
| **天眼查** | ✅ **可调用，返回结构化真数据**；但字段面有边界 | L1：查两家非上市公司的工商股东名单/对外投资/法定代表人，返回逐字段标「来源：天眼查返回」的结构化结果。同日第二轮探针：问「最近一轮融资的投后估值」，答「插件返回字段中**未披露**」——股东/出资类字段有，估值类没有 |
| **万得金融数据服务** | ❌ **已安装但不可调用** | L1：已安装列表里有它，实际调用时 Kimi 答复「万得（Wind）目前也不在可调用数据源列表中」 |
| **同花顺 iFinD** | ⚠️ **可调用，但 API 面不含券商研报检索** | L1：Kimi 自述其 iFinD API「仅覆盖股票基本信息、财务报表、价格行情、公司公告、股东信息等模块，并不包含券商研报检索功能」 |
| 其余 16 个 | **未逐个实测** | 用前跑一次探针查询（见下） |

同一插件家族的边界也**不能外推**：iFinD 能查财务报表，不代表能查研报；天眼查能查股东，不代表能查司法风险全量。每个新数据类型第一次用时，都当「未验证」对待。

另一个 2026-08-18 的实测警告：**点名插件 ≠ 实际路由到该插件**——一次点名三个金融库插件的探针，实际被路由到了天眼查。所以「确认调没调、调的是谁」不能只看你发了什么，要看它自报/工具轨迹（见 `query-and-verification.md` 模式 1 的「自报实际调用」部件）。

## 诚实性证据（这条决定能不能信它的否定回答）

两次实测查询都被显式要求「查不到就明说，不要用训练知识补」：一次直接回答无法检索（研报），一次全部字段标来源并声明「未使用任何训练知识进行补充或修正」。

含义：这条通道的**否定回答基本可信**——它不会拿训练知识伪装成数据库返回。但前提是你在 prompt 里显式要求了诚实条款；不要求，它就退回普通聊天模型的行为。模板见 `query-and-verification.md`。

## 已知缺口：券商研报

截至 2026-08-18，**券商研报检索在 Kimi 的万得与 iFinD 两条路上都不通**——原因不是额度，是结构性的：万得插件不可调用、iFinD 的 API 面本身不含研报检索。

⚠️ 这不等于「Kimi 整体补不上研报」：财新、标普全球、恒生聚源等已安装插件当时未逐个测研报检索。要下整体结论，跑一次不点名数据源的追问。

Kimi 给的人工替代路径（L1 记录）：iFinD / 万得终端的「研报中心」「深度报告」板块，按行业关键词 + 日期筛。

## 探针查询怎么设计

确认「插件 X 到底能不能查 Y 类数据」的最小查询形态：

```
用<插件名>查 <一个确定存在的目标> 的 <目标字段>。
每个字段标明是数据库返回的还是你推测的；查不到的字段写「未返回」，不要用训练知识补。
```

- 目标选**确定存在**的（知名上市公司、真实在营企业）——探针测的是通道，不是目标存在性。
- 回答里出现「未返回/无法检索」= 通道或字段面不通（这是有价值的否定结论）；出现没标来源的字段 = 它在拿训练知识补，这次结果不可用。
- 探针通过 ≠ 该类数据全通：只证明「这个字段面」可调。
