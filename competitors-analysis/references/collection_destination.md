# Route an explicitly selected collection destination

Use this route only when the user selects a team collection for this analysis's
sources or profiles. The executing analyst resolves its existing archive, entry
and producer before saving; finding a Skill or a collection does not authorize
archiving, promotion, migration, publication or messages to the team.

1. Inspect the selected collection's current authoritative entry, matching
   archived sources/profiles, and available producer/review capabilities. Check
   the exact repository/edition and immutable analyzed source version. Reuse a
   matching archive instead of duplicating it. Inspect only the selected scope;
   do not discover an unrelated destination from a directory name.
2. Bind the collection producer's input, destination, permission and human-review
   boundary from its current instructions. Pass the captured source/profile,
   provenance, fixed Git commit or package digest, file:line facts and unresolved
   claims through that owner. Execute only the authorized handoff. If its review
   has not approved admission, report `captured / awaiting collection review`,
   not `in team collection`; do not bypass or simulate the reviewer.
3. Read the admitted entry back through the collection's actual consumer entry
   before claiming inclusion. Record the stable entry link and evidenced source
   version. A producer acknowledgement or draft path alone is not admission.
   Preserve the captured material and any completed steps across interruption;
   resume at the unmet review/readback rather than capturing the source again.
4. Save product-specific adoption/rejection judgments, trade-offs, falsifiers
   and next checks in the project's existing research/current-analysis entry.
   Link the admitted collection source/profile there instead of moving the
   project's decision history. For existing project-backed learning without an
   explicit collection destination, continue saving the existing project scope.
5. If the collection, producer, permission, review or consumer readback is
   unavailable, keep the captured source/profile in its durable bound location.
   Report that location, the exact missing stage and the evidence/authorization
   needed to resume. Keep the pending handoff locatable from the current analysis
   entry; do not claim inclusion, create a replacement collection, lose the
   source, or move all competitor analyses by default.

Keep fixed-source citation and evidence standards from the analysis entry in
both destinations. Keep license/source terms distinct from judgments about
learning from a design or mechanism; collection admission grants no new code
reuse, product-change or publication permission. Use the current source terms
when relevant, without inventing legal conclusions.

## Synthetic acceptance cases

**Selected collection, review still pending.** The user asks to analyze a supplied
repository and put the source/profile in Team Collection A. Its entry identifies
an existing source archive and a producer requiring human admission review.
Reuse the matching source at the pinned commit, produce the cited profile, and
hand it to that producer within authorization. Return `captured / awaiting
collection review` with the durable locator; retain the product adoption judgment
in the existing project entry. After a review approval, open the actual admitted
entry and add its stable link. Approval and consumer readback are separate facts.

**Project learning, collection unavailable.** First, a request to continue an
existing project comparison without selecting a collection stays in the project
entry; a found collection Skill changes neither destination nor authorization.
If the user then explicitly selects Team Collection B and its producer cannot
be accessed, preserve the captured source and cited profile, report that concrete
gap and resume condition, and retain the pending locator in the analysis entry.
Do not report `in Team Collection B` or silently drop the handoff.
