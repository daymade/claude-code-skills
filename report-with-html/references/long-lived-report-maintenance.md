# 长生命周期报告的维护工程（生成器 · 同步 · 单一版本锚点）

> 触发判据（任一即读本文件）：这张页**会再改**（跨天多版迭代）／**嵌入了会变的源文档全文**（协议条款、SOP、规格）／带显式版本／同一页反复交付给同一读者。一次性交付页不需要本文件——**唯一例外是 §7 移动端交付基线**：长页迟早被转发到手机，这跟页面活多久无关，SKILL.md 的窄屏验收指的就是那一节，一次性页也要照它测。
>
> 本文件从长期维护实战提炼；工作实现快照见 `assets/regen-docs-template.py`。

## 1. 嵌入全文是快照不是引用——必须配生成器

报告要让读者"每句话可核到原文"，就得把源文档全文嵌进页面（`file://` 下浏览器不能 fetch 本地文件，CORS 拦死，全文只能烤进 HTML）。烤进去的那一刻它就是**快照**：源 markdown 再改，页面不会跟着变——**漂移的表现是"页面里的条款和实际要签的不一样"，肉眼几乎发现不了**。所以：

- **配一个再生成脚本**，manifest 清单驱动（文件名 / 标题 / 徽章 / 副标题的 SSOT 都在脚本里）；改完任何源文档就重跑。
- **鲜度按需验证，不持久化派生时间戳**：生成器必须支持 `--check`，把按当前源文件计算的期望输出与现有页面比较；一致才新鲜。`全文快照生成于…`、文件 mtime 和“最后更新”都可由源与产物现算，写进页面只会在下一次源变更后漂移。
- **清单外文件警告**：脚本扫源目录，发现 manifest 没列的 markdown 就提示——防新增文档被静默漏收。

> 抽屉**交互**不在生成器里——那是 `citation-drawer` 组件的活（§8）；生成器只把源文档烤成满足组件 DOM 契约的内容、再把组件整块内嵌。改交互改组件、改内容改生成器，各有各的 SSOT。

## 2. 标记块幂等注入（protected regions 的报告版）

代码生成领域的成熟惯例：Go 的 `Code generated … DO NOT EDIT` 文件头、Xtext/JET 的 protected regions——都是用**标记划界"谁管这段"**，让手写与生成共存且再生成不互相破坏。报告页是反向应用：**手写的页里划出"生成器管理区"**（`<!-- DOCS:BEGIN/END -->`、`/*CSS:B*/…/*CSS:E*/`、`//JS:B…//JS:E`）。

实现规矩：

1. **每次整块替换，禁写成"存在就跳过"**。"if marker present, skip" 意味着你改了脚本里的 CSS/JS 常量、产物却永远不更新——脚本从此不再是 SSOT，而你以为它是（字节数不变是这个坑的信号）。正确形状：

   ```python
   class GenerationError(RuntimeError):
       pass

   def put(text, begin, end, block, anchor):
       payload = f"{begin}{block}{end}"
       begin_count, end_count = text.count(begin), text.count(end)
       if (begin_count, end_count) == (1, 1):      # 已有 → 整块替换
           if text.index(begin) > text.index(end):
               raise GenerationError("marker order is invalid")
           head, rest = text.split(begin, 1)
           _, tail = rest.split(end, 1)
           return head + payload + tail
       if begin_count or end_count:
           raise GenerationError("marker pair is incomplete or duplicated")
       if text.count(anchor) != 1:
           raise GenerationError("anchor must occur exactly once")
       return text.replace(anchor, payload + anchor, 1)   # 首次 → 锚点注入
   ```

2. **所有替换先在内存完成，验证整页后再原子落盘**。任何锚点缺失、重复或 marker 不平衡都必须非零退出，且原文件字节不变；禁止 `replace(..., 1)` 没命中也继续报成功。
3. **无 marker 的旧区块必须停下来人工定界**。生成器不得拿第一个 `</section>` 猜嵌套区块终点，也不得因单双引号差异漏认旧 `id`；先核清完整旧区块并加 marker，再运行迁移。
4. **整页语义 id 必须唯一**。落盘前用 HTML parser 统计真实元素 id（不靠双引号字符串 grep）；`#s9`、`#drawer` 或条款锚任一重复都非零退出，原文件字节不变。
5. **生成必须确定性**。不写当前时间、随机 id 或目录扫描顺序；同一源输入重复运行得到同一字节，`--check` 才能成为可靠闸门。

## 3. 混合产物的车道律：动手前先判 SSOT 在哪

页面 = **生成器管理区**（SSOT=脚本常量/manifest）+ **静态叙事区**（SSOT=HTML 本身）。改任何一处之前先回答"它归谁管"：grep 该处附近有没有标记、查 manifest 里有没有这段文案。

- **战例**：文档导航副标题直接在 HTML 里改了，下次 regen 被 manifest 覆盖回旧文案——运行时 DOM grep 才发现。**改产物不改生成器 = 白改。**
- **regen 后双向验证（硬闸）**：先跑生成器，再跑 `--check`；另 grep 两个方向——新内容真进去了、静态叙事区的代表性手工编辑**还在**。只验一边等于没验：前者漏了是脚本坏，后者漏了是标记边界画错、把手写区吞了。
- Edit 工具报「文件被外部修改」＝ regen 刚跑过的**正常信号**，不是故障：重读、确认不冲突、再改。

## 4. 底层事实变更后的叙事反漂移（"改一处漏一片"的报告版）

嵌入区自动跟新 ≠ 叙事区自动跟新。源文档里的规则/结构/人员变了之后，你**自己写的解读段**还在讲旧世界——这是长生命周期页最大的漂移面。收尾动作：

- **grep 旧规则关键词扫全页**：关键词就是"这次变更废掉了什么"（旧机制名、旧期限、旧角色、旧口径）。**`<script>` 里的数据字面量也是叙事**——手风琴条目、图表数据数组藏在脚本里，是最易漏的一类（它们不在"正文"里，肉眼扫不到）。
- **自相矛盾扫描**：同一行/同一条目里新旧规则并存（"一次性付清"与"分 5 期"挤在一个 bullet）＝更早一轮改动的化石，单独 grep 新旧两个关键词的交集行。
- **方向性提醒**：`scripts/reconcile_content_diff.py` 查的是"新版**丢**了旧内容"（合并/重写场景）；本节是反方向——"旧叙事与新事实**矛盾**"（更新场景）。后者没有通用脚本，靠变更关键词清单逐个 grep；写变更时顺手把"废掉了什么"记成关键词清单，收尾就照单扫。
- **旧值不跟着新主张复制**：纯旧值订正直接删，现行叙述只写现行事实。只有改判理由会影响未来决策或防止复发时，才把历史轨迹保留在项目指定的决策日志/时间线；不要在每个现行表述旁复制一份“曾经是什么”。

## 5. 单一版本锚点 + 权威指针随 SSOT 移交

- **版本只保留一个可见权威锚点**。不要在 `<title>`、印章、章节标题和导航各写一份版本；其余位置不带版本。若兼容约束迫使复制，更新前先 grep 全部出现位并在同一次变更里改齐。
- **「以 X 为准」类权威指针也是会变的事实**：报告声明自己的数据源（"数字/条款以协议骨架为准"），当权威移交（骨架→签署稿）时，这句话在全页的每个出现位（lead、§6 说明、文档树图、footer 数据来源）都要一起改，文档树图要重画（新 SSOT 当根、旧权威降为历史推导源）。SSOT 移交是事件，指针是它的副本——事件发生时 grep 副本一次改齐。

## 6. 决策报告的时效边界

长生命周期决策页容易把现行事实、仍有决策价值的历史和纯过期旧值混在一起。按读者未来是否需要它来处置：

| 层 | 判据 | 处置 |
|---|---|---|
| **现在时叙事** | 不带日期、读者会当作现行规则 | **必须当前**——§4 的反漂移扫描就是扫它 |
| **有未来决策价值的历史** | 改判理由会被未来决策引用，或能防止同类错误复发 | 只在项目指定的决策日志/时间线保留，带完整日期与上下文 |
| **纯过期旧值** | 只是旧数值、版本考古或“某日更新了什么” | 删除；不要用取代注把它复制到现行叙述旁 |

整页被取代时按项目文档治理归档；页内历史是否保留，只看它对未来决策是否仍有帮助，不能仅凭“带日期”判定。

## 7. 移动端交付基线（长页会被转发到手机）

长生命周期页迟早被转发到手机上读。交付基线：

- **head 与布局**：`<meta charset>`＋`<meta name="viewport" content="width=device-width, initial-scale=1">`＋**窄屏保护 CSS**。只加 viewport 不加保护会让手机端从"缩小的桌面页"变成"裁切的窄页"——更糟。保护的最小集：auto-fit 网格在窄屏锁列数上限；宽表格放在可聚焦的局部滚动区，别撑破页面。
- **验证窄屏要先证实实际 viewport，再测量**：不要凭 `--window-size=390` 参数或截图宽度认定页面真的在 390 CSS px；先断言 `innerWidth` 与 `documentElement.clientWidth` 等于目标宽度，不成立就改用 DevTools 设备仿真。随后用 `scrollWidth vs clientWidth` 得溢出像素数，并遍历 `getBoundingClientRect().right > vw` 枚举越界元素（排除故意在画布外的关闭态抽屉/遮罩）。
- **改了页内 JS 后做运行时 DOM 验证**：headless `--dump-dom` 后 grep 由 JS 构建的内容（手风琴条目、动态区块）——构建产物在＝脚本没被改坏；只做静态 grep 验不出"JS 字面量里一个引号把整段脚本弄死"。

## 8. 引用抽屉：已组件化（citation-drawer），下列是它的行为契约

抽屉交互（tab 切换 / 正文「第 N 条」linkify / 侧滑定位高亮 / 就地滚动）已经抽成自包含组件 `assets/components/citation-drawer.html`，登记在 `interaction-components.md` 货架。你**不再手写抽屉**——把它 BEGIN…END 整块拷进页面 `</body>` 前即可（生成器 `regen-docs-template.py` 会自动内嵌）。下面这些是固化在组件里的行为契约：

- **滚动定位用 `getBoundingClientRect()` 差值，不用 `offsetTop`**：`offsetTop` 相对最近 positioned 祖先（往往是抽屉自身、含头部高度），不是滚动容器——会稳定偏到错误条款。正确：`delta = el.getBoundingClientRect().top - container.getBoundingClientRect().top; container.scrollTop += delta - 16`。
- **linkify 的 TreeWalker acceptNode 排除 `a/button/code/.cite/.nocite/标题` 宿主**，防已是链接的引用被二次包裹。`.nocite` 是外部引用豁免：指向外部法条或外部文件的编号（POBO §9、架构 SSOT §3.1）不加它就会被链到本文档的同号条款——踩过一个自我演示的例子，正文写着「这是架构 SSOT §3.1（不是本协议的 §3.1）」而这两个 §3.1 都成了链接、点下去正好落到本协议 §3.1。豁免由生成器标注，两条判据：前缀（外部来源名）＋形态（§N(M) 是法条写法，本类文档的子条写 N.M）。
- **子条定位与诚实降级**：引用带子号时先找 `c{N}-{M}` 锚点，找不到才退到母节——而退了就要在状态栏说出来。旧版对子条也照报「已定位并高亮该条」，那个失败分支永远不触发（母节锚点总在），于是读者以为眼前就是他点的那条，实际目标在一屏多以下。
- **组件从 DOM 自读文档名/文件名**（tab 的 `.dt-t`、pane 的 `.dsrc`），不靠生成器注入数据数组——这是它能自包含、脱离生成器独立工作的关键。
- **modal 焦点契约**：引用用原生 button；打开后背景 inert、焦点进关闭钮、Tab/Shift+Tab 留在抽屉；Escape/遮罩/关闭钮关闭后焦点回引用。tabs 用方向键/Home/End 切换并同步 `aria-selected`。
- **抽屉副本不复制源 id**：克隆条款 DOM 时给所有 id 分配抽屉专属 id，并同步 IDREF 属性；定位仍回溯源 id，页面全局 id 在打开和嵌套跳转期间都保持唯一。

两层的接缝是一份 **DOM 契约**：生成器产出唯一 `#s9`，其中唯一直属 `.docwrap` 各含一个 `.dnav` / `.dbody`，它们的直属 `.dtab[data-i]` / `.dpane[data-i]` 一一对应，并包含 `<h2 id="d{i}-c{N}">` + `.dsrc`。组件只在这个 root 内初始化，页面其他区域的同名 class 不参与；正文（s9 之外）出现纯文本「第 N 条」即被 linkify（缺省跳首个有条款锚点的文档，自动避开无编号的说明/一页纸）。契约不成立时页面显示初始化错误，不静默半工作。

**「第 N 条」这个记号可以换**（源文档是 §7 / 「7. 标题」/ Article N 体裁时），但它在**生成器与组件里各有一半正则**——打锚点的在 `regen-docs-template.py`、linkify 正文的在 `citation-drawer.html`——必须同时改。只改一处不会报错：锚点照打、id 唯一、静态检查全绿，而正文里一个记号都匹配不到，引用交互整个是死的。两个文件的头部都写明了这个症状与判据。
