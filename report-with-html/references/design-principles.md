# 设计原则 · report-with-html（泛化，不是抄某一张页的皮）

## 核心：泛化的是"原则"，不是某张页的长相

原话："**我要求的是泛化，不是把它的模板抄过来；你要想清楚它的设计原则是什么。**"

所以：**不存在一套固定的皮**（某组颜色 / 某个字体 / 印章）要套到每张报告上。不同报告有不同 **register**（正式决策书 / 技术架构 / 高管摘要 / 对外提案 / 数据大盘），皮要随之变。要泛化沉淀的是下面这些**原则**——它们决定一张报告好不好，与具体长相无关。`assets/report-template.html` 只是"技术/架构报告"这个 register 的**一个起手实例**（省得每次重搭组件结构），不是通用皮。

## 地基 · 几何胜过文字是领域科学，不是审美偏好

**这条地基的 SSOT 已迁至 `data-visualization-discipline:data-visualization-discipline`**
（该 skill 的 graphical-perception-science 参考文件）——Cleveland & McGill 1984 感知精度排序、
preattentive 加工、Bertin 视觉变量 + Munzner 有效性原则、Tufte data-ink / lie factor /
small multiples，连同这些理论互相冲突的地方，全部在那里，带实证出处。**本文件不复述**：
同一条实证结论写两处，改一处就漂移。

对本 skill 的意义只有一句：**"数据变几何"不是审美偏好，是工程约束**——位置 / 长度的判断
精度与处理速度实测碾压读文字。所以 approved 语料（探针审核）里评分、
份额、时序、严重度全都编成位置 / 长度 / 填充，颜色只留给类别和阈值。页面"不够可视化"是
本 skill 最常犯的问题，根因永远是跳过了"先造量纲"这一步（见原则 2）。

## 成功判据（DNA · "什么算好"）

下面的原则是"怎么做"；另有一组 DNA 是"做得好"的验收标尺（信息密度、扫读性、每块 lead、数值全视觉编码、真实证据、结构化组件、诚实完整）。**完整枚举 + 原话证据的 SSOT 在 `approved-examples.md`**（那是语料库，原话"信息密度、可读性…"就在其首）——此处不复述、不双写。动手前先读它：挑最近 register 的样例真实读一遍再实例化（像 content-writing-discipline 读 golden-samples；规则表达不出整张的密实感/节奏）。

## 原则

### 1. Register 校准（皮随"它是什么 + 谁看"变，但以认可的语料为准、别死套教科书映射）
视觉气质要匹配报告性质与受众，**但落点看实际认可的样例、不套教科书**：他认可的『暖纸 + 宋体 + 朱红』编辑皮，**既用在正式决策书，也用在技术架构汇报（混剪那张）**——凡"给 sophisticated 读者看、要说服/定调"的汇报大类都用它（所以它是 `assets/report-template.html` 的起手皮）；而『工作台 / 数据卡 / 轻解释页』（探针审核、explainer）走更干净的无衬线、更轻。高管摘要 → 大数字少字。**方法**：为当前 register 找一张认可的同类样例（`approved-examples.md`），读它、抽"为什么好"、实例化——别凭教科书或凭空审美。这是 content-writing-discipline §五「受众段位 register」在视觉维度的延伸。

**"皮随 register 变"的精确边界**来自对认可样例的横向 CSS 校准。皮按下表分层，只有最外层随 register 变：

| 层 | 内容 | 变不变 | 证据 |
|---|---|---|---|
| **基底（恒定）** | 页面底色＝**暖纸族 #FAF8F3–#FCFBF8**、卡片白、hairline 浅褐边、低饱和、浅色主题 | 认可报告页均保持暖纸浅色基底 | 工具页可拟物它服务的数据源 |
| **语义框架（恒定）** | 状态色、serif/sans/mono 分工、虚线=空缺、左边框语义条 | 恒定 | 跨 register 保持同一读法 |
| **气质（register 层）** | **accent 色相**、标题 serif 或 sans、印章有无、密度选择 | 随 register 变 | 对外品牌化只改气质，不改读法 |

**对内 sophisticated 报告的既成 token（直接起手、别再发明）**：

```css
--paper:#FBF9F4  --paper-2:#F4EFE4  --card:#FFF
--ink:#211D17    --ink-2:#5B5349    --ink-3:#8A8073
--line:#E7DFCF   --line-2:#D8CDB6
--red:#A62B1F    --gold:#8A6D3B     --green:#3F6B4A   --blue:#33566E
--red-bg:#FBEDEA --gold-bg:#F6EFDF  --green-bg:#E9F0E9 --blue-bg:#E7EEF2
--serif:"Songti SC","STSong","Source Han Serif SC",Georgia,serif
--sans:"PingFang SC","Hiragino Sans GB","Source Han Sans SC",sans-serif
--mono:"SF Mono","JetBrains Mono","Menlo",ui-monospace,monospace
```

**这 19 个是一整套，别只抄前半。** 上一版这里只列了 11 个，漏掉 `--line-2`、四个状态底色和三个字体族——而 `citation-drawer` 组件硬性依赖其中 17 个（它的文件头把这当前置条件写着）。缺的那几个不会报错：组件照常初始化、`var(--red-bg)` 解析成空值，于是引用高亮没有底色、抽屉边框消失，看起来像"这个组件长这样"。五张认可页逐字共享上面这些值。这不是"某张页的皮"，是已收敛的对内标准；工作台变体可按其任务语义换主 accent。

### 2. 结构承载意义 + 先造量纲 + 遮字自测（把定性也变几何）
每个视觉的布局都要**编码含义**：上下=价值/层级、左右=流动/演化、大小/长度=量。装饰性方块阵、**句子加彩色边框**都不算可视化。
- **先造量纲再画**、**遮字自测**——这两条判断层规则的 SSOT 在 `data-visualization-discipline`（通则与自检闸），**本文件不复述**以免漂移。它们对本 skill 的意义：页面"不够可视化"的根因永远是跳过了造量纲这一步。
- **每个自造几何配一行「编码＝含义」解码句**：lead 讲"这块讲什么"（内容），**紧跟一行讲"怎么读"**——declarative 的 X＝Y 句："橙柱＝当月发布账号数（广度），绿线＝单号月均产量（深度）"、"条长＝改动量"、"虚线框＝空洞"。自造组件没有这行就只对作者自明——新几何必须给解码键。
- 对比类靠空间结构揭示洞察（价值栈与抽象几何组件库的正文已迁至 `data-visualization-discipline` 的 visual-form-selection 参考文件）：读者盯着能一眼说出"它揭示了什么"才算数。

### 3. 内容先于装饰：区分事实性 takeaway 与灌结论

页面可以写**由同页数据、机制或一手证据直接支持的事实性 takeaway**，包括标题和图底读出句。页面不能写没有证据锚点的价值判断、口号、maxim、最高级、劝服式对仗或未经证明的因果。

`rg '不是.*是|最[佳强高]|真正的|本质上'` 只负责找**候选句**，不能直接判失败。逐句问：删掉它，读者少知道一个可在本页核对的事实，还是只少一个作者观点？前者可留，后者移到口述或补证据。

### 4. 诚实（真实状态 + 诚实层级）
show 真状态（缺口 / 瓶颈 / 0），别全绿假结论。最要紧的**诚实事实**给最大的视觉权重（hero 数 / 红标），而不是藏起来。

**认可语料里的诚实做法**（组件详情见 `approved-examples.md` 决策·透明组件组）：
- **状态语义**：已核（绿）/ **待核（金，不硬标绿）** / 未知（虚线）。同一指标存在无法解释的口径差异时，如实标"口径待核"，不要硬标已核。
- **口径脚注行**：每页底部灰字一行，写清每个数的口径与截止日；平台不透出的数据也要明确说明。测量覆盖是脚注、不是 hero（§9）。
- **落库对账 footer**：报告页背后的持久化状态也交代——commit hash＋已推/未推色标。**球权分离**：待律师的、待对方的分开标，谁的球在谁那一眼可见。
- **生命周期声明**：一次性页在 footer 写明"拍完即归档"；被取代的页按项目文档治理归档移出读者路径，不文内标"已被取代"。
- **维护者元数据不进读者路径**（同一条原则的另一面，AI 作者高发）：正文里写"第一版这几张卡都没写代价、被独立审阅指出、已改"——这是写给维护者的。读者没参与那次审阅，第一版对他不存在；它读起来像可信度背书，且往往紧挨着"请接受这几条建议"，等于拿一段读者无法核验的过程给结论加分。2026-08 实测一张交底页：3364 字正文里 478 字（**14%**）在讲作者自己的修订史，独立读者的评语是"它描述的是一份已经不存在的文档"。判据：这句在告诉读者**页面现在说什么**，还是**页面曾经说错什么**？后者删掉，或移进项目决策日志。边界：**"我在这里写错过两次，所以这句最该逐字读"是有用的**——它把注意力导向具体位置、服务读者下一个动作；自我背书则只服务作者。

### 5. 克制 > 装饰（anti-slop）＋ 颜色是状态语言、不是装饰
去饱和调色板 · hairline > 粗边重影 · 留白 · **purpose-built 组件 > chart 库默认图**。排布随 register 变；但颜色不是"挑一个好看的 accent"，而是语义系统：

- **语义颜色**（主 accent＋状态色，全部低饱和）：**红**＝主锚/强调/风险/kicker（对内朱红 #A62B1F，对外可换受众品牌红）；**金**＝待定/存疑/待拍板（nav 的"待拍板"高亮、"口径待核" tag、待办框全用金——**"金色=悬而未决"是页面的固定语法**）；**绿**＝正向/已核/推荐（建议选项标绿、verdict ok）；**蓝**＝次要信息域/对方侧（价值交换里"我方给"列）。灰阶承担一切非状态文字。**一个颜色只编一件事**（Munzner），新增语义色前先自问是不是类别色滥用。
- **虚线体系**：**框级虚线＝空缺**（语义）——缺口 / 空洞 / 未知 / 待填 / 未跑通；**行间虚线 hairline＝组内次级分隔**（排版）。两种含义靠位置区分，卡片外框保持实线 hairline。
- **左边框语义条**（4-5px `border-left`）：卡片的判定/类别第一通道（case 卡过=绿左边/拦=红左边、待拍板卡金左边）。比整卡换底色克制，又比小 badge 醒目。
- **阴影接近零**：分区靠 hairline 边框与底色差，**不靠浮起**（Material 卡片堆＝slop 信号）。圆角按卡片与标签分级。深色实心块只留给**终点/目标/收束**，别拿来做普通强调。

### 6. 编辑式层级（组织节奏）
定位标题（masthead）→ hero 数 → **编号章节，每节 lead 先说"这节讲什么"** → 可溯源 footer。这套"文档节奏"泛化到任何报告；具体样式随 register 变。认可语料把每一格做成了固定签名：

- **kicker＝谱系元数据链**：小字大写、`letter-spacing .28–.32em`、红色，内容是「组织 · 项目/域 · 文档类型 · 页序 · 截止日」——一行答掉"这是谁的什么文件、数到哪天"。
- **masthead**：kicker → serif 大标题 → 斜体 sub（sub＝全页目录或方法声明）；底 2px 墨色横线收住。庄重态势页可加旋转印章（时点＋一词定性）。
- **编号章节**：serif 数字套红圈（26px 圆）＋ serif h2；长页配 sticky nav（当前节高亮，**悬而未决的项在 nav 里用金色**）；章节右上可挂 mono 小字**归属标**（该节在分析框架哪一格，如"D 策略 · 断奶"）。
- **每页有落锤**：结尾不渐弱——压轴位放最强的问题/机会型洞察（半年报把获表扬的倒挂 tornado 放末页末节）、或深色 goal 节点收束、或"下一步"跃迁行。扫到最后一屏应该撞上一记结论级视觉，而不是渐稀的杂项。

### 7. 排版做功
标题字要有性格（庄重→衬线，技术→清晰无衬线）；关键数字 mono + tabular-nums 便于扫读对齐。选哪种随 register。量化基线来自认可语料：

- **字体分工**：**serif**＝宋体系——标题、引用原话、庄重定调；**sans**＝苹方系——正文；**mono**＝SF Mono / JetBrains Mono——数字、代码、路径、commit hash。数字加 `font-variant-numeric:tabular-nums`。
- **密度选择**：标准报告页 `15px / lh 1.6–1.68 / max-width 1080–1120`；高密表格页（实体矩阵、变更清单、工作台）`13.5–14px / lh 1.5–1.55 / max-width 1160–1240`。字号阶梯：11–12 注释与口径、12.5–13.5 次级正文、15 正文、19–20 h2、26–35 h1（h1 可 `clamp()` 响应）。
- **中文排版**：全角标点；中西文/数字混排两侧留半角空（"半年 1,563 条产出"）；分隔符用「·」不用竖线或斜杠堆。

### 8. 渲染自验
渲染后必须自己 Read PNG 核对（`frontend-visual-qa` 过 micro/macro/Intent），**没自验过的页不交付**。生成器产 HTML 时加一道机械闸：**先对内嵌脚本做语法检查再渲染**（2026-09-18 战例）：Python 三引号字符串内嵌 JS，JS 里的 `"\n"` 被 Python 解析成真实换行，整页脚本 SyntaxError——masthead 正常、数据区全空，肉眼像「数据没加载」而不是「脚本死了」。提取 `<script>` 块跑 `node --check`（或对应语言 parser），成本一秒；同一作者同一会话 v0 写对 v0.1 写错——记忆不可靠，机械闸才可靠。判据：凡「静态外壳在、动态内容全空」，先查脚本是否整体没执行（语法错），别先查数据。最终交付顺序和形态只认 `SKILL.md` 工作流。

### 9. 受众落地（读得懂 + 讲得出）—— 全库最高频纠正
汇报页的**真实受众常是非技术转述人**（拿它去给老板/总部讲的人），不是你、也不是技术受众。两条硬要求：
- **读得懂**：屏上每个标题 / 标签 / 概念名 / 分数，目标受众**一读就懂**。禁内部品牌名 / 项目代号 / 内部版本号 / 裸算法分 / 黑话表头。§3 允许屏幕放有证据锚点的事实性概念，但概念名本身必须先去黑话。
- **讲得出**：交付前自问"**TA 能拿着这页站起来讲吗**"。页面要**先答掉老板会当场追问的问题**（别让转述人靠页外信息接），隐藏"怎么实现的 / 数据源管道"（受众不关心，如 TikHub 这类实现细节不上给老板看的页）；必要时另附一份"怎么讲"的口播要点（那是口述稿角色，见 content-writing-discipline §三，与页面书面材料分离）。
- **别把"我的取数口径 / 测量覆盖"当洞察上屏**：受众关心业务结论，不关心你的数据管道抓全没抓全。采集覆盖范围是**脚注口径**、不是 hero 视觉。每个视觉过一问："给最终受众看，他据此做什么决策？"答案若关于你的数据完整度＝管道噪音，移脚注。战例与"取数口径当洞察"反模式见 `visualization-patterns.md`。

### 10. 决策卡契约（**四个角色恒定；类名是参考实现，不是规范**）

一个悬而未决的决定对应一张卡。**恒定的是下面四个角色，不是类名**——认可语料里用 `.dq/.dbg/.dvs/.chip(.pick)/.ck/.ct/.cd/.dtag`。**四个角色一个都不能少**。

⚠️ **不要按类名机械核对决策卡**：同名他义会让 grep 得出正好相反的结论——验收只能读角色（见本节末）。

卡片在脱离页面其他内容时也必须自足：

1. **完整问句 `.dq`**：写清要决定什么，不用速记标签。
2. **背景 `.dbg`**：解释现状、约束以及为什么现在要决定；术语第一次出现时就地解释。
3. **选项**：容器 `.dvs`，每个选项一个 `.chip`（推荐项加 `.pick`，可配 `.ck` 标「我的建议」），内含标题 `.ct` 与说明 `.cd`。**代价写在 `.cd` 句子里**，不拆成独立元素——认可语料的写法是一句话同时讲清「这个选项是什么」和「它要你付出什么」（"演示更完整（传上去就出结果），但要求识别服务先上线并稳定运行，现场还得等它跑完一条"），读者读一句就够，拆开反而把卡片打碎。

   **所以验收是读、不是数类名**：逐个选项写下「这句里的代价是什么」，答不出就是缺。**推荐项最容易答不出**——独立审阅曾在同一张页上连中三张卡：非推荐项都老实写了代价，唯独推荐项只有好处。三次全中说明那不是疏忽而是模板手法，效果是**把结论装进版式里**，让读者以为推荐项没有代价。判据与它有没有 `.pick` 无关，只问一句：**这个选项的坏处，写在卡里了吗？**

   **选项还必须覆盖问句的答案空间。** 先读 `.dq` 写下它的可能答案，再看每个答案在选项里有没有位置。战例：问句是「这个算法**你认不认**」，两个选项却是「认，列进附一」与「先不提，等归属时再说」——都在答*时机*，答「不认」的读者无处可去。问句问 A、选项答 B，卡片看着完整，实际把一个可能的答案从页面上抹掉了。
4. **建议 `.dtag`**：写“建议 X，因为 Y”；Y 必须来自卡内可核对的权衡或证据。

布局用同基线并排对照，建议项使用绿色状态语义；关键未知用金色或虚线显式留空。引用的截图或条款放在卡内，调用货架组件原地展开，不强迫读者跳走。已拍板事项移入决策记录；等待其他人的事项单独标明球权。

验收时遮住页面其他内容，只留该卡：陌生读者应能说出背景、选项、代价、建议及理由。否则仍是作者私有速记。

### 11. 标题携带事实性 takeaway（标题是"从数据读出的那句话"，不是栏目名）

认可语料的 h1/h2 通常不是中性名词，而是**带证据锚点的信息句**（对应图表学的 declarative/takeaway title 成熟实践）：

- **h1＝数据判断句**：认可的半年报 h1 是范本——"营销共振正在发生：发布账号 19→47 个 × 单号月产 5.6→10.4 条"、"触达由头部账号撑起，而账号多的省却在沉睡"。读者只读各页 h1 就得到完整论证。
- **register 例外：决策/差距页的 h1 停在问题句**：凡"AI 抛决策 / 摆差距给人判断"的页，标题刻意保持疑问形态——"收不收进认可语料库"、"距离『AI 一键混剪』还差什么"。判断句 h1 等于替读者拍板，违反决策骨架"帮读者判断而非替他判断"的立场——这是 §3 内容边界在决策 register 的镜像。分野：**汇报成效/机制用事实判断句，抛决策/摆差距用问题句**。
- **h2＝「名词锚 · 判断/动作补语」**：前半定位、后半带信息——"打法拆解 · **一台增长机器**"、"加载链路 · **一个没注册的环让整套 skill 加载不到**"。写完标题自测：把全页 h2 连起来读，**是不是一条完整论证链**？是栏目名清单（"背景/现状/分析/建议"）＝重写。
- **与 §3 的边界**：上屏的是**数据支撑的事实判断**——句中每个断言都能指到页内的数或机制；禁的是**价值判断 / maxim / 最高级 / 对仗金句**。判据一句话：**删掉这句标题，读者少知道一个事实吗？少＝合格；只少一个观点＝违规。**
- **takeaway 不只在标题层**：图的下方留一行"从这张几何读出的事实"，作为遮字自测的书面答案。断言必须指向本图数据，不是 maxim。全页标题、章节标题和图底读出句要形成同一证据链。
- **物理隐喻要绑数据**："一台增长机器 / 两台引擎同步上升 / 悬着的决定 / 空着的砝码 / 账号多的省在沉睡"——隐喻让抽象可感，但每个都锚着页内真实机制或数字；没有数据锚的隐喻就是 slogan。
- **lead 与人称随受众**：lead 一律白话（"滑下面的滑块，所有数字实时联动"、"拍掉一项收走一项"）。**对内页用第一/二人称对话**（"摊开给你看"、"你们 0709 的原话"、"我方"）——报告是"我向你交代"的述职文体，不是第三人称公文；**对外客户页收敛为中性陈述**（半年报无"你我"）。

### 12. 差分优先（凡有基线，量必须以变化对呈现）

认可语料反复使用 `A→B`、身份跃迁和 before/after 差分对照。**孤立快照是残缺信息**——当前值没有变化对有力。做法：

- 任何指标有旧值/基线/前态，写成**箭头变化对 A→B**（mono，可附幅度/倍数），别只报当前值。
- 一个动作/决定的后果，画成 **before｜→｜after 差分**（chip=已有、虚线=空洞、划线=被填——见语料库组件表），不是散文描述"收录之后会怎样"。
- 多→一（副本收敛/别名归一/漏斗）用**收敛节点**；身份/阶段跨越用**跃迁行**。
- 对比两态时，落点是**缺口本身**（镜像＋缺口条："缺口＝我方生态位"）——差分不只陈列两边，要点出"差的那块是什么、归谁"。

### 13. 交互克制（默认无脚本；交互必须增加理解或可操作性）

**默认交出无 JS 的静态页**。只在以下情形加交互，且加了就要在浏览器旅程里逐项验证：

1. **交互即论证**：读者拨参数看结果比静态数字更懂机制——参数敏感的计算/估值/分配才配。
2. **数据集导航**：工具页（浏览器/工作台）的列表→详情、过滤、搜索、状态流转。
3. **锚点直达与折叠**：hash 路由（`#p1`/`#g=群名`）＋折叠区 hash 自动展开——服务"引用时给 URL#锚点"的交互契约；折叠让概览不丢细节；引用密集的审阅页可升级为**嵌入源文档抽屉**（`long-lived-report-maintenance.md`）。

**永远不加**：hover 动效、滚动动画、渐入渐出、轮播——装饰性交互全是 slop 信号（§AI slop）。判据：这个交互删掉，读者少理解什么或少完成什么动作？答不上来＝删。

**引用即内嵌（2026-07-20 纠正 · 绝对禁止跳转式引用）**：待拍板卡 / 正文引用概念图、条款、佐证时，证据**直接内嵌在引用处**（缩略图＋点击**原地浮层**放大，关闭后停留原位）；禁止「看 X →」锚点把读者甩到页面别处再让他自己跳回。原话："你让我来回跳转……**绝对禁止这种东西**。你如果需要引用，你就放在这个位置，让我直接能看到图片。"（嵌入源文档抽屉是同一原则的既有形态：**内容来到读者处，不是读者跳到内容处**。hash 锚点仍用于 nav 主动导航与外部引用直达——禁的是"读到一半被迫跳走"。）

**判定该上交互之后，组件从货架取、不现场重写**：`interaction-components.md` 是认可交互的唯一取用处（lightbox-gallery / hash-expand / sticky-nav / 源文档抽屉指针），原样嵌入，新交互认可后按收录闸回写。

## 用真实参考的正确姿势

- ✅ 读它 → 抽"它为什么好"的**原则**（上面各条）→ 按**当前 register** 实例化。
- ❌ 把它的 `:root` 颜色/字体/印章**原样套到每张报告** = 抄皮，不是泛化（本次被纠正的错）。
- 组件的**结构**（pill+badge / 分层 band / 价值栈 / timeline / number strip / masthead 节奏）是**通用的**；皮（颜色/字体/是否印章）是 **register 层**，每张按当前报告调。
- 想不清当前 register 的参考长什么样 → 去找一张真实的同 register 高质量样例读，不要凭空造。

## 迭代

只有新的、可复现的纠正才进入原则；单个项目的状态、计数和版本不持久化在本文件。新范式先进入认可语料，重复验证后再提升为规则。

**改契约（类名、结构、验收方式）同受这条约束——而这是最容易溜过去的入口**：它不像「新范式」那样显眼，看着只是顺手对齐一下现状。2026-08 实测：一张刚做完、尚未被认可、随后被独立审阅查出重大错误的页用了个新类名，我据它一张就改了 §10 的类名契约，理由写成"契约落后于实践"。核对认可语料才发现，认可页用的正是契约里的旧类名、且严格配对——落后的不是契约，是那张页偏离了契约。**判据：改契约前先数认可语料里的用法，不是数手边这张页。手边这张恰恰是最没资格当证据的那一张——它还没被认可，而"我刚写完"给它的说服力是错觉。**
