# 图片与示意图：让读者看见对象、看懂关系

作者在写 HTML 前逐节选图，读者审阅者从成品判断是否看懂，来源验收者核对原件。
图片加载成功只证明文件可用，不证明选图正确或讲清了方案。

## 按读者的问题选图

| 读者要看懂什么 | 默认动作 | 图必须回答的问题 |
|---|---|---|
| 具体产品、设备、场地或界面是什么样 | 查现有素材与官方原图，给关键候选放代表图；外观影响选择时主动补图，不等用户索要 | 这是哪个对象，决策相关的特征在哪？ |
| 怎么接、怎么装、哪里受限制 | 实物／接口／内部图贴着连接或装配示意图 | 哪个部件接到哪，线缆、供电或空间约束在哪里？ |
| 系统、流程、机制怎么工作 | 用结构图呈现实体、边界、连接方向与边上的动作 | 谁依赖谁，什么从哪流到哪，哪个环节还未知？ |
| 尺寸、价格、性能等可核数量怎么比较 | 进入 data-visualization-discipline 选形；数值与几何同源 | 是否有共同基线，未知是否仍可见？ |
| 真实界面或视觉产物哪里有问题 | 用原图／截图及必要的同范围对照 | 缺陷能不能直接指出，而非靠作者说它存在？ |

在已有的页面意图／量纲说明里记下：本节读者问题、要展示的对象或关系、选用的图及依据、
放置位置；拿不到必要原图时写明缺口。不要另建图片数量或覆盖率台账。
纯文字事实可以保持文字；没有证据的数量不能靠画图补造。

产品图与连接图可以展示同一对象，因为前者负责识别外观，后者负责解释关系。
重复同角度照片、换皮重画同一关系、用装饰横幅占据正文，都不能代替缺失的信息图。
不设固定图片配额；以尚未被解释的读者问题决定补图，问题已被清楚回答就停。

## 获取与核对原图

1. 先取当前任务已有的原件和素材，再查官网、官方手册、官方仓库或可追溯的一手发布。
   用当前宿主可用的搜索／浏览能力实际查图；搜索缩略图用于找原页，不作为来源终点。
2. 下载后打开实际文件，核对对象、精确型号／配置、角度和关键细节。不要只看文件名或链接。
   不同配色、不同接口版本或不同配置的照片不能悄悄替代当前候选。
3. 在报告已有的来源记录里保存原页与原图 URL、作者／发布方、获取时间、本地文件和必要的
   型号差异说明；对外发布时同时核对使用许可。网页可访问不等于图片可自由再发布。
4. 在图旁写当前读者需要的说明：对象、要看的特征、官网效果图／实拍／截图的身份及必要限制。
   原图不证明本方案已装配、能放下、性能达标或已部署。缺原图就明确缺口，不伪造实拍证据。

AI 概念图、作者示意图与实物证据要明确区分；生成图不能替代产品原图、实测截图或兼容性证据。
不为补图自行购买素材或使用他人的登录／私有资产。

## 示意图画关系，不给文字套边框

- 节点用可识别的对象，容器表示物理／系统边界，连接线表示已核实的连接或依赖。
  箭头旁写传输、调用、供电等实际动作；不要让读者猜箭头的含义。
- 定性图允许用连接、方向、从属和顺序表达关系，不必虚构分数或比例。
  用现有 `data-geometry` 与 `data-derived-from` 声明关系；选形与编码仍由
  data-visualization-discipline 的 visual-form-selection 参考文件决定。
- 实物尺寸图只有在精确型号的尺寸来源已核实时才按比例画；照片拼贴不宣称共同尺度。
  不能量化的布局标“示意，不按比例”，不能确认的连接保留明确的未知标注。
- 对比方案尽量保持相同读法，例如先识别对象，再顺着连接看到额外设备与依赖。
  使用现有组件、简单内联 SVG 或已支持的 d2；统计图表仍遵守项目图表栈契约。

## 放在论证发生处，保证能读到细节

- 把图片／示意图放在它解释的方案、限制或结论旁边，先给足以读懂的正文尺寸。
  不把所有图片集中到尾部图库，不让读者打开浮层才第一次看见关键接口或箭头标签。
- 用 `figure`／`figcaption` 关联图与说明；给信息图有效的文本替代。
  复杂关系另配邻近的可读说明，覆盖图传达的关键关系；不能只写“架构图”当全部说明。
  实现依据见 [W3C 图片替代文本决策树](https://www.w3.org/WAI/tutorials/images/decision-tree/)
  与 [复杂图片说明](https://www.w3.org/WAI/tutorials/images/complex/)。
- 保持对象和关键细节完整；比较图使用一致裁剪原则。优先 `object-fit:contain`，
  不为等高裁掉接口、供电线或限制部位。只有细节确实需要放大时才加入现有 lightbox-gallery；
  其行为与键盘验证由 interaction-components.md 拥有。
- 单文件报告内嵌图片；多文件报告使用真实本地路径并随交付带上文件。
  不把远端热链当唯一图片，验证用户实际打开的文件中图片与图例正常显示。

## 沿现有验收职责检查

作者在浏览器旅程检查加载、清晰度、图文邻接、裁切、阅读顺序与放大交互。
读者审阅者执行 independent-review-prompt.md 的图像问题：从可见成品说出对象、关系和结论，
指出“有图但无助于理解”或“没有图所以必须猜”的位置。
来源验收者按 SKILL.md 的 Provenance 核对图与原件的身份和事实边界。
自动闸不能判断选图是否有帮助；图片数量、存在的 `img` 标签和绿色加载结果不作为替代验收。
