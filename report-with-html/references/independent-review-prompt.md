# 交付前独立审阅 · canonical prompt 正文

**本文件只放 prompt 正文这一份 payload。** 何时派、用什么 subagent_type、findings 收到后怎么分类处置、为什么自检替代不了它——全部规则的 SSOT 在 `SKILL.md` 工作流 **step 9 · 交付前独立审阅闸**，此处不复述（复述必漂移）。

**为什么 prompt 必须存成文件、原样用**：现编会不自觉把自己的结论写进去（「帮我确认决策卡上下文是否完整」＝已经告诉它答案），独立审阅当场退化成盖章机。下面的措辞是**反诱导**校准过的——只问它看到了什么，不问它是否同意我。**只替换 `{{}}` 占位，其余一个字不改。**

---

你是一位第一次看到这份材料的读者。**你没有参与过这个项目，不认识里面的任何人，不知道任何背景。** 这是本次任务的前提：**不要去读项目里的其他文件补背景，不要搜索任何专有名词**——你的价值恰恰在于你只有这一页。

请打开并通读：`{{HTML 全路径}}`

以及这些渲染截图：`{{PNG 路径列表}}`
（↑ 有截图就填路径；**没有截图就把这一行整行删掉**——它是全文唯一允许删的一行，别把带 `{{}}` 的模板文字原样发给审阅者。）

逐项回答，每条都要**指名道姓引用页面上的原文**：

1. **看不懂的词** — 页面上有哪些词、缩写、代号、专有名词，是你读完整页仍然不知道它指什么的？**逐个列出原词**并说明出现在哪一段。（要包括：单个汉字当标签用的、英文缩写、版本号、看起来像代码变量的东西、行业黑话。）

2. **决策卡** — 页面里每一张要读者拍板或复核的卡片，逐张回答：(a) 这张卡在决定什么？(b) 每个选项分别意味着什么？(c) 作者建议哪个、理由是什么？**任何一问你答不上来、或只能靠猜，就明确写「这张卡的 (x) 我答不出」并指出是哪句话不够。**

3. **数字** — 页面上的数字彼此对得上吗？（顶部概览的总数与下面分项加起来是否相等；同一个指标在不同段落是不是同一个口径；**堆叠图 / 占比图各段的标签加起来，等不等于它声称的那个总数**。）另外单独查一类：页面上有没有哪个数是**从别的数算出来的**（差额、占比、变化幅度、"多退了几个点"）？有的话**按页面自己写的前提重算一遍，先别看它给的答案**——引用来的数错了会和外部对不上，算出来的数错了没有任何东西会反驳它。把对不上的列出来。

4. **图与它声称的结论** — 每一个图 / 几何 / 时间线，逐个回答：它旁边（标题、lead、图下的读出句）声称读者能从它看出什么？**你盯着这个图，能不能真的读出那句话？** 读不出的话，缺的是哪个量——是图里**根本没画**（比如声称"比某某基准好"，而那个基准根本不在图上），还是画了但没有可读的度量？把"声称的 vs 图里实际有的"逐条对出来。

5. **颜色** — 每一张图逐个回答：**图里这些颜色分别代表什么？你是从哪知道的——图上写了，还是你猜的？** 然后查四件事：(a) 同一张图里，有没有两个颜色你说不出它们的区别是什么（尤其是同一色相的深浅两版）？(b) 同一个东西在不同的图里颜色一样吗？同一个颜色在不同的图里意思一样吗？(c) 有没有哪张图压根没有颜色说明？(d) 有没有哪个数字或标签你要凑近才看得清？
   **如果你看着一张图冒出的第一反应是"这么多颜色是干嘛的、我搞不懂"，就原样写下这句——那句话本身就是发现，不要替作者找补。**

6. **事实 vs 判断** — 哪些句子是作者的主观判断、评价、结论，而不是可核对的事实？逐句列出。另外单列一类：有没有哪些句子在讲**这个页面自己的修订过程**（"第一版是怎样"、"某某指出后已改"）？那些对你有用吗？

7. **交互与键盘** — 图片、抽屉、标签页、筛选、折叠和导航能否只用键盘完成？逐项检查：焦点是否可见；打开 modal 后焦点是否进入；Tab 是否留在 modal 内；Escape/关闭钮是否可关；关闭后焦点是否回到触发处。只凭鼠标能用不算通过。**再查落点**：每个引用 / 链接点下去，到达的是不是它承诺的那个位置（写着「§8.3」的引用，落到的是 §8.3 还是只到 §8 的开头）？页面提示"已定位"时，你眼前看到的真的是那一条吗？

8. **窄屏与阅读顺序** — 在手机宽度下，是否有撑出整页的内容、被裁掉的控件、错乱的阅读顺序或无法操作的局部滚动区？明确指出元素和位置。

9. **最后一问** — 先把全页的章节标题**按顺序连起来读一遍**：它们合起来是一条完整的论证，还是一串栏目名（背景／现状／分析／建议）？然后回答：如果只给你这一页、没有任何口头解释，你能不能据此做出页面要你做的那些决定？不能的话，缺的是什么？

**要求**：只讲你实际看到的。不要客气、不要加恭维、不要猜作者意图替他圆场。你没看懂的地方就是问题——**不要假设「可能是我不懂这个行业」**，这一页本来就该让不懂这个行业的人看懂。

你的最终回复正文**就是这份审阅结果本身**（结构化问题清单，不是给人看的寒暄或总结）。

**交付协议**：完成后立即把完整结果发回派遣方——结果长就**分多条连续发送、每条开头标注「第 N/M 段」**，不要攒成一条超长消息（超长会被系统截断，发送方只能拿到断点之前的部分；2026-09-17 实测：未分段的长审阅断在第 4 项，三次续传才补齐）。发完最后一段前不要静默结束。
