# Recover an HTML page and its attachments

Use this after the user asks to restore a former page, including a saved browser
tab that points into an expired job directory. The result is the recovered page
and its usable dependencies, with unresolved parts named. Reading or hosting an
existing page does not authorize a redesign, new business conclusions or recovery
of unrelated browser data.

## 1. Bind the page and its recorded version

Retain the original URL/path, title, fragment and tab-group/order when supplied.
Check whether the original file still exists before searching history. A broken
temporary path is a locator; it is not proof the page content has disappeared.

Use indexed discovery and one exact Session through the
[vanished-artifact workflow](workflow_examples.md#recover-vanished-temporary-job-artifacts).
That workflow owns checkpoint precedence, companion roots, later deletion and
the distinction between file-history bytes and a Write checkpoint. Preserve any
recorded later Edit or shell-generated change as a version gap until the final
bytes can be established; do not silently label an earlier Write as final.

Recover into a fresh output directory. Keep original files and the current
project tree intact. Record the source Session, checkpoint/version, original
path, recovery path, byte count and SHA-256 from the recovery evidence. A matching
hash establishes the selected bytes, not that all page dependencies were found.

## 2. Inventory the dependencies the page actually consumes

Read the selected HTML and its relevant local script and style dependencies. Resolve relative
URLs against the original page location and any recorded base URL, rather than
the new recovery directory. Check:

- image, poster, audio, video and source URLs, including `srcset` and CSS `url()`;
- local scripts, styles, embedded JSON/data and runtime `fetch` or module imports;
- links to other recovered pages and local documents needed for the requested use.

A source filename shown in a caption or a JSON provenance field is not necessarily
a resource request. Separate consumed URLs from descriptive paths before calling
them missing. Follow only the explicit dependencies needed by the selected page;
do not recursively serve a project, history store or private evidence directory.

For each consumed dependency, first check its recorded local path and the page's
known output directory. If absent, inspect the already selected Session and its
verified continuation when that can resolve the gap. Use the
[original tool evidence route](../SKILL.md#original-tool-callresult-evidence)
for one relevant call/result; retain complete selected payloads in a private file
when the bounded response clips them. Do not replace this with a whole-history scan.

An original tool result may contain an image's bytes as an embedded payload. When
those bytes are present, recover only that selected payload, preserve its recorded
media type, and retain the tool-use ID and physical source coordinates with the
decoded file's hash. A screenshot ID, thumbnail URL, clipped base64 prefix or
textual image description alone is insufficient to recover those bytes. The
history reader exports evidence; it does not automatically extract every binary
format. Keep any necessary format-specific extraction confined to the selected
evidence and state its coverage separately.

## 3. Preserve the recovery state of each object

Use separate states instead of a single page-wide success flag:

| State | Evidence required | What it permits |
|---|---|---|
| Original bytes recovered | Present original/checkpoint/tool-payload bytes, source identity and matching hash | Attribute the file to that exact recorded version |
| Regenerated from originals | Original inputs plus the recorded generator, parameters and input/output identities | Use the new output with its method and limitations stated; do not claim original byte identity |
| Screenshot only | An identified historical screenshot, with its source | Read the captured view; the original interactive page remains missing |
| Missing or unverified | Named dependency and checked source boundary | Show the gap and the next available recovery source; do not invent substitute content |

When regenerating a poster, frame sequence or other derived asset, retain the
original media and the recorded extraction method. Matching image counts or
durations does not establish that regenerated bytes equal the historical files.
Keep regenerated files distinguishable from recovered originals.

A screenshot does not restore playback, hidden panels, downloads, original audio
or timeline data. An HTML copy also does not transfer old `localStorage`, IndexedDB
or browser-session review marks to a new HTTP origin. Recover and verify such state
separately only when it is available and within the requested scope; otherwise
mark it unverified. Do not interpret a fresh page's zero reviewed items as proof
that the user never reviewed them.

Keep one compact mapping with the recovery output:

| Original path/URL | Recovered path | Source Session + record/checkpoint | SHA-256 | Recovery state | Read/play result or remaining gap |
|---|---|---|---|---|---|

Use the actual values. Unknown source/version/hash stays unknown; an unavailable
asset does not acquire a fabricated row claiming successful recovery.

## 4. Open the recovered page and return to the user's task

For local HTTP preview, load `report-with-html` and follow its
[existing HTML restoration route](https://github.com/daymade/claude-code-skills/blob/main/report-with-html/references/local-http-preview.md#existing-html-restoration).
That owner handles the explicit served snapshot, URL rewriting, HTTP readiness,
large media and the actual delivery-browser check. Rewrite references only in
recovered/served copies; keep the recovered source bytes and their identity.

Verify the expected page content and its primary requested operation in the actual
delivery browser: for example, read the historical decisions or play and seek a
representative referenced video. Check the consumed dependency inventory; a
working HTML response or one screenshot does not certify the other assets.
Keep file recovery, attachment recovery and rendered functionality as separate
observations. Label missing images, unavailable audio, login requirements and
unverified external pages at their relevant entries.

When the requested content is readable and the necessary operation works, return
to the original reading/review task with the verified entry and remaining gaps.
Do not start new-report styling, masked-render grading or a new authoring-review
cycle merely to transport the old page. A separately requested redesign uses the
ordinary report-authoring workflow.
