# Use Mobbin evidence for an existing application

Load when Mobbin screens or flows can answer a selected interface question, or
the user explicitly requests that research. The executing agent collects and
interprets this evidence; no screenshot score establishes product fit.

## Bind the question and available access

Start with the target application's actor, object and unfinished journey from
the entry. Search for a reference that can inform that question: identifying a
result, inspecting its source, copying an action or returning to prior work.
Keep an already adequate interface as a valid outcome.

Discover Mobbin capabilities in the current host's tool catalogue and read the
selected tool's current input/output contract. Reuse an existing authorized
connection or browser session through its owning workflow. Do not hard-code a
remembered API, infer account access from a visible tool name, or install a new
integration to make this optional source appear ready.

When access is unavailable, name the missing observation. Continue independent
authorized work when Mobbin was optional; use another permitted source only
for claims that source can establish. When the user required Mobbin research,
keep that lane incomplete and state its recovery condition. Neither case
authorizes broader account access or invented reference findings. After access
returns, probe it and resume the selected question rather than restarting the
application's completed work.

## Capture the exact reference and evidence limit

Inspect the actual screen or ordered flow, not only search-result metadata.
Keep the evidence in the task's authorized research location with:

| Field | Capture |
|---|---|
| Source identity | Canonical Mobbin URL and exposed screen/flow ID, product, platform and capture date; retain edition/version when supplied, otherwise unknown |
| Material inspected | Actual screenshot or flow-step locators; for a saved file retain its path and content hash so a later caption can be checked against the same bytes |
| Observation | Visible grouping, labels, controls and state; identify which flow steps were actually inspected |
| Limit | Behavior not observed, including persistence, failure/recovery, live interaction and implementation |

Treat a screenshot as evidence of visible organization. Ordered captured screens
can show a represented sequence; they do not establish that the reference
product was interactively tested. Keep a live-product observation separate and
claim it only when that authorized journey was actually exercised. Do not
invent missing steps, use metadata as a screenshot, or caption a mockup as a
live reference. Keep paid or private reference assets outside the public Skill
bundle; reference access does not establish redistribution permission.

## Adapt the mechanism through the target journey

Apply the entry's mechanism disposition table to the inspected reference.
Name the target's existing equivalent before selecting a change, then bind:

1. The observed mechanism and the current user result it could improve.
2. The smallest adaptation and the target contract it must preserve: object and
   version identity, unknown/error states, permissions, drafts or return context.
3. The part rejected or still unverified, with the deciding reason.
4. A falsifiable target-app journey using representative actual content, plus
   the evidence still needed before claiming implementation or adoption.

For example, adapt a list's secondary identifier when same-named target objects
are hard to distinguish. Verify that the user opens the intended exact object,
follows its correct source, and returns to the same query and reading position.
A reference's attractive `Completed` badge supplies no evidence for changing
the target's definition of completion or resolving its unknown states.

Return the selected increment to the existing engineering and acceptance
workflow. Record source checks, synthetic examples, actual consumer use and
production adoption separately. Stop collecting references once the evidence
selects the authorized increment or establishes the precise missing observation.
