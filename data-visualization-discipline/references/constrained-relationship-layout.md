# 带空间与职责约束的关系图

适用于网络、机房或架构图同时表达“在哪里、做什么、连到哪、是否已实现”。执行者按下列步骤处理；首次读者试读验证可理解性，用户的审美反馈决定其审美接受。此页是判断方法，不安装布局引擎或承诺自动验证审美。

## 布局之前固定含义

把实体、接口、关系与显示坐标分开。位置可编码真实方位，分区可编码房间/组织边界，层次可编码职责；同一位置不要同时暗示未经确认的网络域或调用顺序。展示坐标不是比例尺，未按比例时不要让卡片大小暗示设备体积。

以合成的楼宇网络为例：区域甲、乙作为行，接入、路由、交换、终端作为列，可以同时表达地点和职责。它只是适用时的候选。读者只问调用关系时不必强加房间；用户要求单一融合图时，也不要因布局工具更容易而拆成两份要读者自行拼接的图。

选择现有自动布局或约束式网格之前，写下必须保持的分组、端口侧、主干通道和阅读方向。让工具处理适合它的部分；局部参数化定位也可用，不把“用了算法”当正确证据。[ELK 的图模型](https://eclipse.dev/elk/documentation/tooldevelopers/graphdatastructure.html)区分节点、包含关系、端口和边；[端口约束](https://eclipse.dev/elk/reference/options/org-eclipse-elk-portConstraints.html)展示了固定侧、顺序和位置等选择。这里借用其表达能力，不指定所有任务必须采用 ELK。

## 让线路和注记服从主线

- 同一类跨区线路走固定通道，局部关系在所属区域展开；交叉无接点时不能看成汇合，标签不能压在线上。
- 颜色与虚实各编一个维度，例如颜色区分介质、虚实区分现有/计划，并在图例解码。不能把未知接法画成与已确认连接相同的实线。
- 突出本次读者需要追踪的主干，再放设备与注记。退役说明、未知字段和局部无线引用不应盖过现役主线，也不能为了干净省掉承重未知。
- 一个终端是一份身份；不同终端有独立接线时保留独立支路。不要为图形对称改写实际连接。

## 独立验收判据

| 判据 | 取得什么证据 | 什么不够 |
|---|---|---|
| 事实正确 | 对原始实体清单和接线事实逐项核对，追到具体两端 | 总数相等、生成器退出成功 |
| 阅读可用 | 首次读者从正常阅读尺寸的成品指出位置、角色、指定起终点之间的路径和未实施部分 | 元素没有碰撞、作者解释后才懂 |
| 视觉质量 | 并看实际旧新渲染，比较主次、密度、留白、字号和噪音；用户有明确审美要求时交用户看成品 | 复用了旧源码、Agent 宣布更美或评分通过 |

操作者可用现有模型检查、渲染和试读覆盖事实与阅读风险；没有通用检测器保证整体美观。审查结论绑定被审版本和判据，不将旧版通过转给新图，也不因事实审查通过宣称用户已接受。

## 小改动保留已有阅读路径

新增一个终端时，先保留其余分区、稳定实体 ID 和主链路，只排该区域及必要的局部走线。比较模型差异，确认没有无关接线/状态变化；再看局部和全图，防止局部更整齐却让主干变差。需要整体重排时，先指出哪条阅读路径已无法局部修复。

停止于本次改变的事实、可读性和交付条件均有对应证据；审美尚待用户判断时如实标明。一个新的终端事实不自动授权换视觉风格、重新跑全套评审或再设计全部区域。
