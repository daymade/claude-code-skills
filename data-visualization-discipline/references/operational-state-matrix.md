# 运维状态矩阵：当前证据与风险

执行者在画矩阵前，按项目已有的观察、新鲜度和告警契约确定每格表示什么，再让读者能回答「现在是否可用、哪一路仍不确定、哪里需要处理」。以下是合成案例，不是任何真实服务的状态。

## 1. 固定观察身份和口径

从项目权威源取得目标、探测地点、监控身份、观察时间、新鲜度及状态字典。推送与轮询并存时，按项目的先后判据选当前观察；页面不另造状态机。分别表达：

- **当前观察**：本轮判据允许用于当前结论的值。
- **未知及原因**：当前证据缺失、来源失败、陈旧或停用；按项目字典显示。
- **历史值**：可供追溯的上次在线、离线或证书天数，带历史身份，不用于支持当前健康结论。

同 URL、同地点仍可能有多个监控。保留各自身份和结果；需要目标级摘要时，采用项目已有判据，并让构成该摘要的分歧可见。计数只覆盖声明的当前探测范围，历史记录数不等于当前探测数。

## 2. 会误导下一步的案例

| 合成输入 | 读者需要看见 | 不能据此得出的结论 |
|---|---|---|
| T0 在线；T1 当前观察明确为未知 | 当前未知，必要时附上次在线及其时间 | 沿用 T0 报当前在线 |
| 来源本次失败，只有旧快照 | 来源失败及历史观察，目标当前状态按项目契约表达 | 目标已从监控器删除，或旧值仍证明当前在线 |
| 最新成功且完整的快照遗漏一个期望监控 | 期望监控缺失及其身份 | 来源失败与监控缺失是同一事实；资产本身已删除 |
| 同目标、同地点，监控甲在线、监控乙不可达 | 甲与乙的名称、身份和分歧 | 只取第一条在线，或用平均值冲淡失败 |
| HTTPS 当前可访问，证书剩余 6 天；示例策略的严重阈值为 7 天 | 在线状态与证书严重风险同时可见 | HTTP 成功足以支持「没有待处理风险」 |
| 没有当前探测数据 | 未配置、未覆盖或未知的实际原因 | 空集合支持「全部在线」 |
| 已确认一个会话在等答复，问题详情尚未读到 | 一个待处理会话；问题数量未知或详情未读全 | 「0 个待答问题」，或因详情为空把会话从待处理筛选移除 |
| 已读到两个问题，剩余范围尚未覆盖 | 「已读到 2 个」及覆盖限制 | 恰好只有两个，或未读部分为零 |
| 同一范围的新鲜完整读取确认没有待答问题 | 该范围内的已确认零条 | 因保留 unknown 而拒绝所有合法的零值 |
| 选中并放大一个伙伴；当前执行观察缺失 | 选中焦点与未取得当前观察分别可辨 | 放大、全彩或动画证明正在执行 |
| 父任务在执行；伙伴仅有历史参与和旧回报 | 父任务当前状态、伙伴历史回报及其时间 | 团队成员全部仍在执行；回报等于成果已采用 |
| 团队共 30 位；当前读取窗口覆盖 8 位，其中 3 位确认执行 | 总数、已读范围及范围内确认执行数各自标明 | 全队仅 3 位执行，或其余 22 位空闲 |
| 同批一个登记项损坏，另一个会话有独立有效的执行观察 | 采集不完整诊断与健康会话的执行事实同时可见 | 单项失败覆盖同批所有会话；健康会话证明来源完整 |

证书阈值来自项目策略；本例不建立通用天数规则。跨地点汇总剩余天数时，先按项目契约排除不可作当前证据的读数，再说明采用了哪些有效观察和汇总口径。不能把缺失或失败读数填成 0，也不能悄悄跳过它们后声称全覆盖。

让摘要、分组、筛选与详情消费项目已有的同一状态解释；作业生命周期、原生执行态和问题详情覆盖分别保留。执行者用同一身份的输入逐项核对，不从标签颜色或数组长度重建状态。交互路径仍按下方实际页面验收；本参考不增加执行权限或另造状态机。

为 Agent 群体视图分别列出选择焦点、当前执行证据、历史参与、回报／采用与读取覆盖；它们可以同时存在，不合并为一种忙闲颜色。原生归档须读项目认可的归档字段，历史记录本身不证明已归档。让独立读者说出每个强调和数字代表哪一项，再与同身份、同观察时刻的权威输入核对；不从回报时间或读取条数推导完成百分比。

## 历史窗口与采样时钟

先从项目读取合同确定当前快照与历史范围各用哪个判定时刻。所选窗末端、查询点时间、原生采样时间、接收时间和页面当前时间分别保留；只在项目支持历史读取时使用历史窗口口径。晚些打开固定历史窗口不能自动把其中有效样本判成陈旧；正常历史样本也不证明服务现在正常。

项目若另有原生采样时钟或采集探针，按其身份和配对合同独立检查。新查询点不能给旧采样续期，其他卷或来源的时钟不能补给本行；缺字段时保留原值及具体缺口，不补零或改写采样时间。未来窗口按项目合同拒绝或限定合法读取范围，不用未来窗末端把尚未发生的样本判成正常。

用以下合成对照检查读者答案；期限和配对条件由测试输入的项目合同提供，本例不建立通用 TTL 或时钟算法：

| 合成输入 | 读者需要看见 | 不能据此得出的结论 |
|---|---|---|
| 历史窗口内的查询点和本行原生采样均在该窗口的有效期限内；页面稍后打开 | 所选历史时段、原值和原生采样时间；重开页面不改变该历史判定 | 因当前墙钟已前进而称该历史样本陈旧；或称服务当前健康 |
| 查询点有效，本行原生采样在该窗口的判定时刻已超期 | 原值仍保留，明确指出原生采样超期 | 用新查询时间或新接收时间覆盖旧采样 |
| 原生时钟缺失或只找到其他身份的时钟 | 本行缺少匹配采样证据及其身份；沿原读取器补证 | 借另一卷或另一来源的时间判本行正常；把缺失写成零 |
| 同屏有历史范围来源和仅支持当前快照的来源 | 各自按项目支持的读取模式判定 | 为消除误报把所有来源统一改成历史时钟 |

## 3. 同时校准危险与健康情况

由执行者列出预期读者答案，交给独立于绘图实现的项目记录或合成输入裁决：

1. **危险控制**：当前未知不能显示成当前在线；同地点的失败监控不能被隐藏；示例 6 天证书风险不能被在线状态遮掉。
2. **健康控制**：在已声明范围内，来源新鲜、完整且全部当前监控在线、没有达到策略阈值的风险时，可显示该范围的在线结论。不能为抓风险把正常输入也判失败。
3. **近边界控制**：知悉只影响项目允许收起的事项，不自动改变观测事实；历史值保留其用途，但不得冒充当前值。
4. **覆盖控制**：说明哪些目标和地点在判据内、哪些未知。任一当前观测缺口都不能被人数、监控条数或 worker 存活的计数替代。

定规格在阶段 2 完成；绘制后按既有交付闸核对口径、颜色语义和渲染结果。需要证明交互或修复后的实际页面时，交给 frontend-visual-qa 的同状态用户路径验收。API、截图文件路径或组件存在本身不证明读者看到了正确风险。

停止条件：每个显示单元能回到其观察身份与时间，未知和分歧清晰，健康/危险控制都能让读者得出预期答案。没有工具自动证明这个语义判断；执行者保留「输入 → 显示 → 读者答案 → 权威对照」证据，不以自评绿灯代替它。
