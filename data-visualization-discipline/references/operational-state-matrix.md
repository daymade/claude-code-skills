# 运维状态矩阵：当前证据与风险

执行者在画矩阵前，按项目已有的观察、新鲜度和告警契约确定每格表示什么，再让读者能回答「现在是否可用、哪一路仍不确定、哪里需要处理」。以下是合成案例，不是任何真实服务的状态。

## 1. 固定观察身份和口径

从项目权威源取得目标、探测地点、监控身份、观察时间、新鲜度及状态字典。推送与轮询并存时，按项目的先后判据选当前观察；页面不另造状态机。区分三件事：

- **当前观察**：本轮判据允许用于当前结论的值。
- **未知及原因**：当前证据缺失、来源失败、陈旧或停用；按项目字典显示。
- **历史值**：可供追溯的上次在线、离线或证书天数，带历史身份，不用于支持当前健康结论。

同 URL、同地点仍可能有多个监控。保留各自身份和结果；需要目标级摘要时，采用项目已有判据，并让构成该摘要的分歧可见。计数只覆盖声明的当前探测范围，历史记录数不等于当前探测数。

## 2. 会误导下一步的案例

| 合成输入 | 读者需要看见 | 不能据此得出的结论 |
|---|---|---|
| T0 在线；T1 当前观察明确为未知 | 当前未知，必要时附上次在线及其时间 | 沿用 T0 报当前在线 |
| 来源本次失败，只有旧快照 | 来源失败及历史观察，目标当前状态按项目契约表达 | 目标已从监控器删除，或旧值仍证明当前在线 |
| 最新成功且完整的快照遗漏一个期望监控 | 期望监控缺失及其身份 | 来源失败与监控缺失是同一事实；资产本身已删除 |
| 同目标、同地点，监控甲在线、监控乙不可达 | 甲与乙的名称、身份和分歧 | 只取第一条在线，或用平均值冲淡失败 |
| HTTPS 当前可访问，证书剩余 6 天；示例策略的严重阈值为 7 天 | 在线状态与证书严重风险同时可见 | HTTP 成功足以支持「没有待处理风险」 |
| 没有当前探测数据 | 未配置、未覆盖或未知的实际原因 | 空集合支持「全部在线」 |

证书阈值来自项目策略；本例不建立通用天数规则。跨地点汇总剩余天数时，先按项目契约排除不可作当前证据的读数，再说明采用了哪些有效观察和汇总口径。不能把缺失或失败读数填成 0，也不能悄悄跳过它们后声称全覆盖。

## 3. 同时校准危险与健康情况

由执行者列出预期读者答案，交给独立于绘图实现的项目记录或合成输入裁决：

1. **危险控制**：当前未知不能显示成当前在线；同地点的失败监控不能被隐藏；示例 6 天证书风险不能被在线状态遮掉。
2. **健康控制**：在已声明范围内，来源新鲜、完整且全部当前监控在线、没有达到策略阈值的风险时，可显示该范围的在线结论。不能为抓风险把正常输入也判失败。
3. **近边界控制**：知悉只影响项目允许收起的事项，不自动改变观测事实；历史值保留其用途，但不得冒充当前值。
4. **覆盖控制**：说明哪些目标和地点在判据内、哪些未知。任一当前观测缺口都不能被人数、监控条数或 worker 存活的计数替代。

定规格在阶段 2 完成；绘制后按既有交付闸核对口径、颜色语义和渲染结果。需要证明交互或修复后的实际页面时，交给 frontend-visual-qa 的同状态用户路径验收。API、截图文件路径或组件存在本身不证明读者看到了正确风险。

停止条件：每个显示单元能回到其观察身份与时间，未知和分歧清晰，健康/危险控制都能让读者得出预期答案。没有工具自动证明这个语义判断；执行者保留「输入 → 显示 → 读者答案 → 权威对照」证据，不以自评绿灯代替它。
