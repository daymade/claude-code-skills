**这份文件回答"该画成什么形状"。** 判据介质无关；**具体组件的实现**（HTML/CSS 片段、pptx 形状坐标）属于实现层 skill，不在这里。

## 通则：把定性变几何的三步

1. **先造量纲再画**——每个抽象名词（改动量 / 严重度 / 完成度 / 把握 / 依赖 / 频次）先降维成**有上下界的刻度或有限枚举**（1–5 / 0–100% / ok-gap-done / 实线-虚线）。有了量纲，长度 / 格数 / 位置 / 透明度才有处落。**跳过这步就会退回写句子。**
   **造不出量纲怎么办**：老实用一行 note 写清楚，**别硬塞假图形**——没有量纲的"图形"比一句话更糟，它假装编码了信息其实没有。这是合法降级路径，不是失败。
2. **位置 / 长度承载"量"，颜色只承载"类别或阈值"，一个载体只编一件事**（不双编码）。面积会被系统性低估、透明度/明度只承载"序"不承载精确量——需要读者读出准确值时一律回到位置 / 长度（精度排序见 graphical-perception-science 参考文件 §1）。
3. **过程 / 关系用"等距容器 + 语义连接符"**：横排 `▸` = 时序管道、竖排 `↓` = 层级瀑布、首尾 `↺` = 飞轮、`≈` = 类比、`└` = 派生树、`left%/width%` = 时间轴、顶边粗色 = 严重度、虚线/调暗 = 待定。节点只放 3–5 字，重话进旁边 note。

**每个自造几何配一行「编码 = 含义」解码句**：lead 讲"这块讲什么"，紧跟一行讲"怎么读"——"橙柱 = 当月发布账号数（广度），绿线 = 单号月均产量（深度）"、"条长 = 改动量"、"虚线框 = 空洞"。**自造组件没有这行就只对作者自明。**

## 映射表：内容类型 → 形式

| 内容类型 | 视觉形式 | 空间语义 / 揭示什么 |
|---|---|---|
| 价值流 / 用户旅程 / 流水线 | **pill + badge + zones + loops** | 横向 = 流动顺序；zone 分段；badge = 状态注解；loops = 反馈回路 |
| 同一系统的多个视图 | **分层 band** | 纵向叠层（旅程/产品/技术/数据）；同列 ≈ 同一价值链环节 |
| 人物 / 角色 / 责任 | **头像 chip** | 头像 + 动作 + 锚点标签；比文字卡有"人"的实体感 |
| **对比 / 借鉴 vs 优势 / 我们 vs 竞品 / 商品化 vs 护城河** | **价值栈**（见下方详解） | 上层薄 = 核心/独有、下层宽 = commodity；**揭示价值集中在哪一层、对方缺哪层** |
| 数据结构 / 域关系 | **域盒 + 跨域桥** | 两域 + 中间桥，揭示"怎么 join 起来" |
| 出路 / 路线 / 演进 | **飞轮 / timeline** | 节点串成环/线，now = 绿、goal = 红 |
| 关键数字 | **number strip** | mono tabular-nums，hero 数；诚实数字标红 |
| **指标相对基线/前态的变化**（有旧值就别只报新值） | **箭头变化对 A→B**（可附幅度倍数；多→一用收敛节点、身份跨越用跃迁行） | "19→47" 比 "47" 多一半信息；**差分是第一等信息** |
| 实现状态 | **色徽标**（绿已通/琥珀瓶颈/红缺口） | 标注在骨架上，不做独立矩阵 |
| 模块调用 / 架构结构（关系复杂时） | **auto-layout 图**（如 d2） | 让工具排版，别手搓坐标 |
| **具体数值 / 评分 / 占比 / 状态**（能用图形就别用文字） | **填格条**(离散 1-5) / **进度条**(连续 %) / **堆叠占比条**(份额) / **色徽标**(状态) | 长度/填充 = 大小，一眼可比；数字 mono 附旁 |
| **内容本身是视觉的**（镜头/成片/截图/帧） | **真实缩略图带 / 播放器 / 真截图**（不用抽象方块代替） | 直接 show 真图，读者眼见为实 |
| **单个对象的多维档案**（评分+标签+详情+溯源） | **富数据卡**（verdict banner + 标签 + 评分格 + 进度条 + 分段条 + 折叠原文） | 一卡装全维、可折叠下钻；密度高但分区扫读 |
| **参数敏感的计算 / 估值 / 分配** | **交互计算器**（滑块 + preset + 实时联动 + 高亮结果 + 解释句） | 让读者拨参数看结果，比静态数字更懂机制 |
| **节奏 / 归属 / 演进阶段** | **横向时间轴**（dot 实心=已定/空心=可选） | 横 = 时间流，关键 caveat 红字标 |
| **两个同构对象比对**（主体/方案/竞品） | **镜像对比**（两卡 + ≈/vs + 属性 dl） | 并置同属性行，差异一眼对齐；比价值栈更适合"两个都要展全属性" |
| **需求 vs 供给 / 匹配 vs gap** | **匹配连线图**（左列需求 → 右列供给，连线色 = 匹配度、存疑标金虚线） | 揭示哪些诉求被满足、**哪条存疑**——比两列并排更能点出"错配在哪" |
| **两个对立维度的倒挂 / 错配**（资源多≠产出高、账号多↔播放低、投入↔回报错位） | **对向条 tornado**（同一行：左维度向左展开 + 右维度向右展开，值标固定中缝） | 一行内左长右短 = 资源多产出低、左短右长 = 以少博多，错位一眼可见——比两个独立排名榜直观。**渲染修法**：条占满时数字加浅底衬底防同色隐身；柱值贴底避让线值。**双向混选实体**：既选左端典型也选右端典型，只按一维排 top-N 会漏另一半倒挂 |
| **权衡决策 + 关键未知**（留/走、买/建，且决定项是空的） | **决策天平 + 空砝码**（两盘对比 + 中间"?"砝码） | 揭示"两边都摆着，但决定往哪倒的那个变量是空的" |
| **机制 / 口径 / 阈值本身**（等式、比例、上限） | **公式行**（`＝ × ÷ ≤ ≥ max()` 紧凑代数一行，关键量加粗） | 一行代数比一段散文精确且可复核 |

## 抽象 / 定性内容 → 几何组件

**这是最常犯"写成句子"的地方。** 没有现成数字的内容同样要变成形状。

| 抽象内容类型 | 几何组件 | 量纲 → 形状 | 源 |
|---|---|---|---|
| 某维度改了多少 / 覆盖几成 / 强度 | **填格条** ▓▓▓░░ | 定 1–5 或 0–100%，点亮 N 格；颜色叠阈值（≥4绿/3黄/≤2红）；缺席显"—"不是 0 | 探 |
| 输入→转化→输出 / 某流程走到哪 / 哪环坏了 | **状态管道**（节点整体按状态上色，坏的红）+ `▸` | 位置 = 顺序；节点底色 = 该段健康度 | gap/exp |
| **多个并列因子/结论 → 一台机器** | **机制链 / 因果链**（节点 = 步骤/因子，`→` 边上标转化的证据数） | 把散落的"三个因"连成机制，读者看到的是机制不是清单 | 派生 |
| 多来源 → 汇聚一点 / 依赖几项 | **汇流 / 依赖柱**（虚线柱 = 地基未夯） | 柱数 = 源数；从多源收束到一点再扇出 | gap |
| 定性问题清单 + 排了轻重 | **承重排序卡**（顶边粗色 = 严重度，序号 = 排名） | 顶边色编严重度；证据句红字点关键数 | gap |
| 一段过程里哪几节发生什么 / 哪节有效 | **分段条**（轨内色段，left% = 起点、width% = 时长） | 位置 + 宽度都承载时间；不写时间戳列表 | 探 |
| 疑似 / 未确定 / 未来态 | **虚线待定节点** / dim 调暗 | 实线 = 已实现、虚线/灰 = 没跑通 | exp/gap |
| N 处副本 → 1 处 SSOT | **收敛节点图**（N 实心点 ──▶ 1 SSOT 点；不齐长度 = 已漂移） | 副本数 → 点/段数 | 派生 |
| 完成度 / 状态机 / 生命周期卡在哪 | **进度分段轨**（绿已完成/琥珀待办/虚线可选 + "你在这里"竖线） | 段填充 = 完成态；一眼看到停在哪格 |  |
| 问题→修法→依据 的多段映射 | **映射行**（每行一个角色色标胶囊 + 一句） | 胶囊色 = 角色（诊断/修复/出处） |  |
| 两实体同构 / 类比 | **镜像对照**（`1fr auto 1fr` + `≈`，主角描边） | 并置对齐属性行；`≈` = 同构 |  |
| 一个权威源 → 多派生 | **派生树**（root + `└` 缩进枝，SSOT 带徽章） | 缩进 = 从属层级 |  |
| "这才是目标 / 结论" | **深色节点**（浅色排里唯一深底白字） | 明度反差最强、从同排拔出 | gap/exp |

## 价值栈（对比类默认用它）

任何"借鉴 vs 护城河 / 我们 vs 竞品 / 通用件 vs 独有能力"，**不要**做成两列 chip。做成**上下两层的栈**：

```
[对方在这层怎样：空/弱]          ← 点破对方在核心层缺什么
┌─────────────────────────────┐
│ 核心层 · 独有（定价权·抄不来）  │  ← 上层"薄"（条目少但价值高）
│  [能力A] [能力B] [能力C]      │
└─────────────────────────────┘
        ▲ 价值/防御力集中在这一薄层
┌─────────────────────────────┐
│ 基建层 · 借来的成熟件（可平替） │  ← 下层"宽"（commodity）
│  [组件A←来源] [组件B←来源] … │
└─────────────────────────────┘
[对方在这层怎样：同样借鉴/可平替]
对比揭示：一句话点破洞察。
```

**为什么它揭示了洞察、两列 chip 没有**：
- **纵向 = 价值/防御力高低**——空间本身说"价值集中在哪"。
- **每层标"对方在这层怎样"**——直接把"对比"变成"对方核心层是空的"这个结论的**证据**。
- 读者一眼得出："基建人人可拼，壁垒在那薄薄一层核心，且对方缺它。"

## 多视图分解：加一个视图必须加信息

**产物不止一个视图（多页 / 多节 / 多面板）时最容易犯的错**：把一页的内容按主题切成 N 页——看着"结构化"了，其实零信息增量、密度反而下降。

> 原话："**你只是把之前的一个页面拆成了三个页面，并没有带来任何信息增量，信息密度反而下降了。**"

**正确模型是"总 → 分"**：每个视图沿**一个不同的维度**把总量拆开、露出聚合掩盖的结构，不是把同一批控件按"成绩/机制/质量"这种主题标签分箱。

**判据**：从 N 个视图到 N+1 个，新那个要**揭示聚合层看不到的结构**，而不是复述它。

**动手前先定"分解轴清单"**：一个总量（如"1074 万播放"）能沿哪些**正交**轴拆——平台 / 时间 / 账号集中度 / 区域 / 质量分层？每轴是一个不同的分析问题、配一个不同的几何。**每个视图认领一个轴，视图之间不重画同一个量。**

这是 SKILL.md "一个对象只画一次"在**跨视图**的延伸：单视图内不换形状重画同一实体，跨视图则每个拆不同轴。

**收尾自测**：把新加那个视图与前一个并排，问"这个拆的轴，前面出现过吗？"出现过 = 冗余，删或换轴。

**"要几个视图"由分解轴的数量定，不由"内容太多想分开"定**——**两页密排 > 三页摊薄**。为排版舒服把一个轴摊成两页，是零信息增量的拆分。

> 战例（半年报）：把半年报切成"成绩单/增长/质量"三页，月度产量柱**同时出现在第 1、2 页** = 同一个量画两遍、纯冗余，密度直接垮。

## 缺口 / 未知也要可视化

诚实不只是"露瓶颈徽标"。**那个决定结论却还空着的关键变量**——要给它一个**视觉空缺**（虚线"?"砝码 / 空格子 / 问号盒），而不是省略不画。

让读者一眼看到"这里是空的、它却是决定项"。

> 例：留/走决策里 outside option 那个空砝码 = 决定往哪倒的关键，可视化成天平上缺的一块，比写一句"这个数未知"权重大得多。

## 节点标签优先用真原话

可视化的节点 / 标签 / 卡片文字，**能用当事人真原话就别用 AI 概括的抽象名**。

真原话是最硬的事实——带出处的一句原话，比 AI 写的一句判断更实、更可信、且不掺 AI 的推断。做诉求 / 心态 / 立场类节点前，先 grep 真原话作锚点。

检索纪律与出处格式见 `content-writing-discipline` 的 raw-material retrieve 一节。
