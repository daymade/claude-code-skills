# Example Session: 录音笔 → 妙记转写稿修正（四人对话 · 品牌名链条 · dashboard 结案）

2026-07 实战全程（私人实体已化名）。这份材料的价值在三个可复用判断模式：**文内自证链**、**二遍裁决的拒绝判据**、**enqueue 粒度决定 dashboard 裁决质量**。

## 场景与格式识别

录音笔内录（3 段共 68 分钟）→ 1.3x 加速上传妙记 → 妙记转写导出 52 分钟。妙记导出格式（与本地 ASR 管线的 `[mm:ss.mmm - ...] SPEAKER_xx` 不同）：

```
2026-07-24 23:34:03 CST|52min 11s

Keywords:
品牌、受众、携程、商业、小红书、…

Transcript:
说话人甲 00:00 
目标来来来拆解任务的话，那是不一样的。
```

要点：`说话人 HH:MM` 标签行**已由用户手工标注**——是身份 SSOT，修正全程零触碰（diff 验证：`diff | grep 说话人名 = 0`）。**Keywords 行同样是 ASR 产物，同样要修**（metadata 不是神圣的——它里的村名若写错，未来 grep 会静默失败）。

## Stage 1：applied 0 是正常的

`applied: 0, deferred: 1`——字典对高质量妙记 ASR + 全新语境几乎零命中，**AI pass 做全部真活**（SKILL.md 开头已校准）。唯一 deferred「新一→星壹」（line 566「这是最新一代」=马桶语境）是字典误报，native pass 判 kept_original 关闭——**deferred 不是待应用清单，是待裁决清单**。

## 文内自证链（高置信修正的判据）

同音 + **同一文件里已有正确写法** = Confident fix，不走搜索阶梯：

| ASR 碎片 | 正解 | 自证锚点 |
|---|---|---|
| 云溪院/云西苑/溪苑/许溪月（11 处） | 云溪苑 | 同文 8 处写对 + 创始人姓名链（某高端民宿品牌，化名为「云溪苑」；误写含缺字/同音/形近三类） |
| 大牛/大六 | 某主理人账号名 | line 626 亲口报出账号名（「大牛」高频真实词，只在该语境改） |
| 十楼 | 石龙（村） | line 686 写对「石龙的小伙伴群」 |
| 再地 | 在地 | line 440 写对「从在地的故事」（文旅行业术语） |
| 许溪月 | 云溪苑 | 语境指机构不指人（「许溪月那边/他们」=品牌方） |
| 可定状态 | 可订 | 订房平台语境 |
| 嫁给机子 | 架个机子 | 拍纪录片语境 |

**词典沉淀的边界**：只有 from 侧是**非词/罕见形**才 `--add --domain`（云溪院→云溪苑 ✅）；from 是**真实词/真人名**的进 domain context file 作 trap（大牛→某账号名、许溪月→云溪苑、十楼→石龙——「大牛」是高频真实词，进字典必误伤）。

## 二遍 subagent：11 候选 → 修 7 拒 3

独立冷读 agent 报 11 条，**候选不是结论**，逐条裁决的拒绝判据（比接受更有教学价值）：

- **拒「松赞的 like → Lite」**：like 在口语完全成立（「松赞 like 款」），且上文引擎刚正确识别 Light——**ASR-capability counter-check**：引擎证明过能识别 Light，这里写成 like 更可能是说话人真说了 like
- **拒「做皮了吗 → 做疲了吗」**：下文「皮糙肉厚的」证明「皮=麻木」是这群人的真实口语——**intelligible real words 不改**
- **拒「云豆宝宝 → 芸豆宝宝」**：作品/吉祥物名可能故意谐音「云」（云南）——专名命名意图无法证伪时保留

接受的都是**同音 + 文内自证**（200 分别→分辨：212 行同句型写对；1451 老家→老江：1463 行「他叫老江」；1514 石库→石窟：当地真实景点名）。

## enqueue 粒度决定 dashboard 裁决质量（#24 战例）

20 条 uncertain 入队 → dashboard 裁决。**事故**：#24 enqueue 的 `original` 拖了整句「我们的民宿就完了」，用户 override 品牌名「栖云」→ CLI 的 file_edit 把**整句**替换成「栖云」，上下文被吞。修法三层：

1. **enqueue 粒度**（根因，零成本）：`original` 只放 ASR 误写的那个词，整句放 `context`——SKILL.md step 7 已写明
2. **dashboard UI**（防线）：override 输入框上方恒显「替换范围（整段）：「<original>」」，输入远短于原文时琥珀色警告——已修（app.js `updateOverrideScope`）
3. **裁决后抽查**：dashboard 批量裁决完，逐行 grep 核验落地 + 抽读关键行语义（本次靠这步发现丢字）

## 收尾复利

- 品牌名三种 ASR 写法统一回填 + 入典——下次同语境录音 Stage 1 自动修
- queue 20 条全关闭，skipped 的 4 条记进 context「下份录音再遇到时重新提」
