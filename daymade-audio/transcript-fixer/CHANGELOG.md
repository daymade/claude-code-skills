## [Unreleased]

### Added
- **Review reasons now have an explicit promotion loop instead of ending at `decision_note`.** After a batch review, the skill now uses `--list-review --review-status all --json` because the human-readable list never prints the note and a reopened item can carry one while back in `pending`. It routes each non-empty note by meaning to the domain context, false-positive retirement, domain dictionary, or people roster, and makes the state-machine boundary explicit: storing a note never executes it, `append_note` only runs on acceptance, overrides drop suggestion-specific actions, and kept/skipped verdicts run none.

### Fixed
- **The replacement remedy asserted a diagnosis the parser cannot make (independent review of the fix below).** The new message stated flatly that the bullet "reads 正确 → 误识, the reverse of the documented **误识 → 正确**" — but all the parser established is that the TO side *would* parse as FROM variants, which is not the same fact. A correctly-written bullet whose FROM genuinely holds a space is a real, ordinary shape: ASR splitting a Latin compound, `**Chat GPT → ChatGPT**`. Measured, that bullet was told to swap; obeying produced `ChatGPT → Chat GPT`, which scans for the **correct** spelling and offers the ASR error as the correction — warning gone, coverage satisfied, file inverted. By the standard the previous entry set ("a remedy the reader can apply with nothing changing is the defect"), a confidently wrong diagnosis is worse than a no-op, and this change's own thesis was that a message must not claim what the parser does not know. The diagnosis is now conditional and names both branches, leaving the direction to the author — the only party who knows which side the transcript contains.

  Three smaller findings from the same review, each reproduced before acting: the swap was offered after verifying only **one** half of it (the old FROM was never checked as a TO), so obeying could land the reader on a second warning instead of a scanned trap — it is now offered only when both sides survive; a variant list longer than six printed an honest count beside a silently truncated list (`8 variant(s): a1 … f6`), now marked `…(+N more)`; and the lost-TO-side message blamed "a descriptor", which measurably does not reject anything (`姓名 李四` parses) — it names the punctuation instead, so the reader is not sent after a rule that is not there. Five tests added, calibrated in both directions (5 fail against the preceding commit, 42 pass after). One of them initially passed against both engines through a wording accident and was strengthened to assert the honest fallback rather than the absence of one phrasing.

- **The trap-scan coverage warning prescribed a remedy that could never work.** Third and final pass on the check added in #256 and repaired in #263. The whitespace branch told the author to "put it on its own bullet" — but that branch only fires when the bullet produced **nothing** scannable, and moving a term to a line of its own does not remove the whitespace inside it. Measured on the two real instances: both were *already* alone on their bullet and still warned. A remedy the reader can "apply" with nothing changing is the same defect as a warning that misfires — it is how an operator learns to skip the whole section, and it takes the check's genuine finds down with it (one real trap in this corpus had never been scanned at all). The note being replaced was itself written to avoid prescribing a nonexistent fix, and then did.

  Both real instances turn out to be a bullet written `正确 → 误识`, the reverse of the documented `**误识 → 正确**` — the FROM side is what gets scanned for, so it must be the ASR output. Rather than guess, the warning now asks the parser directly whether swapping the sides would parse, and prescribes only what that returns, naming the variants it would recover (`test / pest / pass / past`). Where a swap would not help either, it states the gap and prescribes nothing. The lost-TO-side warning likewise said only that the entry was gone, never what to change; it now names the cause (a descriptor or backticks *inside* the side — outer ones are stripped, inner ones reject the entry).

  Verified end-to-end against the six real context files rather than fixtures: warning count unchanged at 5 (this is a message-only change and structurally cannot create a warning), and applying each prescribed remedy to the real file content clears that warning **and** converts a previously-unscanned trap into a scanned one (3→4, 52→53, 2→3 entries). Five new tests, calibrated in both directions — four fail against the pre-fix engine, all pass after. `test_error_recovery.py`'s pre-existing environment-dependent failures are unchanged.

### Added
- **Numbers — the error category the dictionary structurally cannot reach.** A dictionary rule needs a *stable* wrong→right mapping; numeric misrecognition has none (`80` becomes `800` in one recording and `18` in the next), so no amount of dictionary work touches it — while the entity-level ASR literature consistently ranks numbers and named entities as the worst-performing categories, with a numeral's continuation tokens worse than its leading digit (exact percentages circulate in secondary summaries and are deliberately not quoted, having not been checked against primary sources). The leading digit is usually right and the tail is where it breaks, which is precisely why a wrong number still reads fluently and survives every proofread. SKILL.md now carries the three sub-classes with a distinct settlement path each — **magnitude** (a restated amount gaining or losing a zero; settle by arithmetic against another figure in the passage), **measure word dropped** (`30+` for a spoken "30 家"; recover from the object), and **polarity inversion** (a stated *ceiling* transcribed as a *floor*; settle by finding the other statements of that number in the same session and preferring the one carrying a limiting modal). Polarity is called out as the dangerous one and deliberately left un-automated: the sentence stays grammatical, the digits stay right, and only the meaning reverses. Also documents the two-recording case as the strongest available evidence — independent systems have uncorrelated numeric errors, so disagreement localises and agreement settles — and names it as the manual two-system instance of **ROVER** (Recognizer Output Voting Error Reduction, NIST 1997) so the reader can reach the literature; a "redundant" second capture of a meeting is a reference transcript for exactly the values that matter, and `fetch_minute_audio.py` covers the single-recording case.
- **`scripts/scan_numeric_consistency.py` — numeric-slot damage detection.** Catches a distinct failure with the same symptom: a global replace aimed at something else landing *inside* a numeral. The canonical trigger is relabelling a speaker whose diarization label is a bare digit — the replace fixes the speaker lines and silently corrupts every number containing that digit (a stock count, a shelf code like `3+1`, a discount rate, the date in the title), leaving a transcript that reads perfectly. An over-broad dictionary rule produces the same signature. The needle list is the dictionary's own `to_text` values, which makes the check self-referential in a useful way: **the strings this toolchain writes into transcripts are exactly the strings that must never appear inside a number**, so nobody has to hand-maintain a list of forbidden neighbours.

  Three design constraints came out of calibration against a real 222-transcript corpus rather than from the drawing board, and each is documented at its line because each looked *more* thorough in the version that failed: **(a)** widening from the matched term to its surrounding CJK run is bounded to two characters per side — an unbounded walk to the run boundary swallows a whole phrase, lands next to an unrelated digit, and fired 97 times on healthy text versus 46 real hits; **(b)** only the digit-*before*-term direction counts as evidence, because term-followed-by-digit is simply how Chinese is written and matching it drowned the detector in ordinary prose; **(c)** frontmatter and metadata lines are blanked, since a title's leading date is structurally identical to the damage and never is damage. Final calibration: all four real damage shapes detected, 0.004 findings per file across the healthy corpus.

- **A design that was tested and rejected, recorded because the negative result is the reusable part.** The first version of this scanner also flagged same-unit numbers an order of magnitude apart inside a window — the shape of "a unit cost restated with an extra zero". On the 222-transcript corpus it fired 280 times with exactly one true positive: deliberately contrasting two magnitudes ("不是 10 条，是 100 条", "从 5 个变成 50 个") is utterly ordinary speech and is arithmetically indistinguishable from a dropped zero. Narrowing it to require a *restatement* connective made it worse — it killed the one true positive (a rhetorical `是不是` matched the contrast list) and left the false ones, because `也就是说` in business speech overwhelmingly introduces a **derived** quantity ("月租 6 千…也就是说一年 7 万 2"), not a restatement. The conclusion is a boundary worth keeping: **this discrimination is not reachable by lexical rules; it needs the semantic read that the native AI pass already performs.** The detector was deleted rather than shipped, and the magnitude class now lives in SKILL.md as a reading protocol instead of a scan.

### Added
- **Native-pass evidence tooling — three manual evidence loops are now single commands.** The native correction pass used to re-pay three hand-rolled grep loops on every transcript, and each was the kind of friction a tired operator silently truncates: (a) **trap-scan** — `fix_transcription.py --scan-traps --context-file <domain-context.md> -i <transcript>` parses every `**误识 → 正确**` entry out of the domain context file (multi-variant FROM sides via `/`, family-name prefixes like `族名系（变甲/变乙/变丙` scan only the parenthesized variants, `**X = …勿修…**` confirmed-correct records report keep-as-is) and locates every variant with line number + context window; the no-hit list is printed so "scanned and absent" is distinguishable from "never scanned". The bold-pair parser rejects prose look-alikes (a context file's own commentary discussing an anchored rule, or text caught between two unrelated bold spans, matches the regex shape but fails the word-character constraint — both false-entry shapes were caught by scanning a real production context file, and are pinned by regression tests). (b) **corpus probe** — `--probe <term> --corpus <dir>` measures a term's real-meaning frequency across the project's transcripts (per-file counts + sampled context windows + the verdict criterion attached), answering the question the jieba/common-word validators structurally cannot: not "is this a real word in Chinese" but "is it ever real *in this project's corpus*". Both intuition directions fail without the measurement — a "real word" whose every in-corpus occurrence is the mishearing (bare rule is safe where the word-checker scared you off), and an "obvious error form" carrying real meanings all over the corpus. Also wired into `--add` as `--check-corpus --corpus <dir>` (prints the evidence before the rule is written; advisory, never blocks). (c) **multi-domain Stage 1** — `--domain a,b` loads the union of sibling project domains in one pass (`--apply-domain` trusts the whole union; `--add`/`--approve` stay single-domain and fail fast on a list), because one project's vocabulary routinely lives in several domains that grew at different times, and the 0-correction hint now excludes every requested domain so the not-yet-loaded siblings are exactly what remains listed. SKILL.md's trap-scan step and Quick Start, `false_positive_guide.md` (the corpus-frequency decision table), `domain_context_guide.md` (the machine-read entry shapes), and the parameter references are updated to match; `normalize_domains` is shared between CLI and service/repository layers so a raw string and a parsed list behave identically everywhere (an early version normalized only at the CLI and two pre-existing hint tests caught the mismatch — the function now self-normalizes).
- **New tests** across `test_trap_scanner.py` / `test_corpus_probe.py` / `test_multi_domain.py` / `test_add_guards.py`, including the prose-false-pair rejection shapes and the review-driven guard cases; full suite failure set is byte-identical to the pre-change baseline (`test_error_recovery.py`'s pre-existing environment-dependent failures).

### Fixed
- **Independent-review findings folded back (11/11 accepted after independent reproduction).** The adversarial pass (fresh `claude -p` context, artifact + reader-spec only) caught: `--check-corpus` silently printing the "zero-risk" verdict on a typo'd `--corpus` path and then writing the rule — a missing directory now fails fast there exactly as `--probe` already did, because an unsearched corpus reads identically to a clean one; `--apply-domain` gating on the RAW `--domain` string, so a malformed `",,"` normalized to no-filter (ALL domains loaded) and then got blanket-trusted — a silent downgrade to `--apply-all`; it now gates on the normalized list. Cross-domain `from_text` collisions resolve deterministically (earliest `--domain` entry wins) instead of falling out of SQLite scan order. The trap parser now requires bullet-line-start (a mid-line `**上文**单→双**下文**` shape produced a fake `单→双` entry that would have reported every 单 in every transcript) and treats parens without `/` as a comment (`减（减少的减）` scans 减, not the comment text). `--add` writes the normalized domain (a trailing comma used to pass the count check, then die in the pattern validator with a misleading "invalid characters" attribution); `--approve` gets the same single-domain fail-fast. Probe output prints its sampling coverage (2/file, 8 total, file order) and the verdict aid now says "every SAMPLED occurrence", so a capped sample can no longer read as a complete census. Confirmed-correct keep-words (勿修/非误识/确认正确/保留原样) and the FROM-parenthesis grammar are now documented in `domain_context_guide.md` Rule 0, and the corpus decision table's zero-occurrence row no longer contradicts itself.

### Added
- **`--reanchor-review` + enqueue anchor-verbatim validation — the queue now repairs anchor drift instead of stranding items on it.** Two failure shapes used to leave review items permanently unresolvable: context/line drift (the file was edited after enqueue, so the fail-closed guard refuses every verdict — real incident: an item enqueued with a *paraphrased* context died in the reviewer's hands and the file got hand-edited around the queue) and file-gone (the transcript moved, was renamed, or a temp staging copy was cleaned). The new CLI verb `--reanchor-review ID...` repairs both against current disk state: in-place drift re-locates `original` in the file (preferring lines that still match the RECORDED context snippet over mere distance — picking by distance alone and then overwriting the snippet with the chosen line would have fed the resolve-time guard a fabricated right answer for the wrong occurrence), and a gone file is searched for under the recorded parent dir plus every `--reanchor-root` (unique content match re-points the anchor, with `--reanchor-to FILE` as the explicit escape when search is ambiguous — itself refused when the original is absent, and resolved to an absolute path so macOS `/tmp` symlinks can't fork one physical file into two dedup identities). Explicit action packs get their `file_edit`/`append_note` paths rewritten on re-point; the UPDATE claims `status='pending'` (mirroring resolve's concurrency guard) and refuses to create a dedup-key collision with another pending item. Enqueue-side, `--enqueue-review` now validates that `original` (and `context`, when given) appears verbatim in the declared file and exits 3 with `rejected_unanchored` in the JSON when not — authoring errors die at enqueue instead of at verdict — and repairs line hints only when they point *outside* the resolve window (±3) of a unique match (an over-eager auto-repair rewrote a functional hint and broke the dashboard's context fallback; repairs are now reported to stderr). `stage1_deferred` items are exempt: their `from_text` is the engine's evolving text after earlier rules applied in-memory, legitimately absent from the input file.

### Added
- **`scripts/fetch_minute_audio.py` — one command from minute token to wired-up dashboard audio.** Replaces the by-hand recipe that every transcript re-paid: it fetches the signed URL, downloads through the SSRF-guard fallback, verifies the audio and the transcript sit on the same timeline, and prints the `audio:` frontmatter line. Three by-hand failures are now encoded rather than described — the envelope is JSON-parsed at `data.download_url` (a regex scrape leaves escapes literal and yields a truncated URL that downloads a redirect stub), the proxy is disabled for the domestic API call, and a wrong `--profile` (a minute is a per-tenant, per-user resource) is reported as the likely cause when no URL comes back. The timeline check reuses the dashboard's own `_TS_LINE` shape rather than a looser scan: an early permissive version matched a wall-clock timestamp sitting in YAML frontmatter, read the transcript as 12.4 hours long, and rejected a perfectly healthy pairing — calibrated both directions before shipping (healthy pairing exits 0, a 76-minute recording against a 7-minute transcript exits 1).
- **Post-verdict sibling sweep (Review Queue section, doc-only).** A resolved review item edits exactly one span: when the original text occurs several times the guard picks the occurrence nearest the recorded line hint whose context matches, refusing only when nothing near the hint matches — so multiplicity alone never blocks a verdict, and the other occurrences are simply left standing, including on the line just edited. Measured: ten items resolved, four left six more occurrences behind, two on a line a verdict had already touched. The workflow now ends a batch with the enumerate-then-sweep procedure, with the traps that make a naive sweep worse than none: the default listing shows PENDING only (the items you just resolved are the ones it hides — `--review-status accepted|overridden`); the replacement must come from `resolved_text`, because on an override `suggested_text` still holds the *rejected* suggestion and that is what the listing prints; sweep only `entity`-kind items, since `homophone`/`wording` verdicts are judgements about one sentence; step 4's referred-to-third-party carve-out still applies, as does caution for verdicts the human reached by listening to a single clip; sweep after the batch, not between verdicts, or a swept occurrence fails a still-pending item's anchor; and finish an override with `--add`, because the queue drops `dict_add`/`append_note` on override — leaving the single strongest signal in the loop (a human correcting the AI) as the one case that never compounds.
- **Enqueue-before-rename ordering rule (new step 9b, doc-only).** Queue items store the transcript's absolute path and resolve against it, so a rename (step 10), an archive copy, or step 9's promote path silently strands every pending item — each verdict then fails its anchor with nothing explaining why. Archiving cuts the other way too: a verdict applied after the copy fixes the working file while the archived one keeps the error, which is the same "the correction doesn't travel" failure the derived-document sweep exists to prevent.
- **Derived-document propagation sweep (Native AI Correction step 9, doc-only).** A transcript is not a terminal artifact: within hours it is mined into notes, decision logs, analyses, and outbound messages, all written from the *uncorrected* text and carrying no timestamp that would make a reader suspect the spelling. Every **entity** correction now ends with a `git grep` for the old form across the project and a fix of the derived documents in the same pass. Real case: a misheard person-name reached two analysis documents and was one draft away from a message going to the people being discussed. Paired with the cheaper upstream habit — cross-check a proper noun against the people roster the first time it leaves a transcript, which removes the propagation problem instead of recovering from it.
- **Cross-language proper nouns are the documented exception to the sound test (step 4, doc-only).** "Judge by SOUND" makes sound-similarity *sufficient* evidence of identity; it was being read as *necessary*, which silently blocks a whole class of real fix. A name spoken in one language while the engine transcribes another can surface phonetically unrelated to its canonical form — and as something that reads like an ordinary *different* real name. Measured case: one person surfaced as three separate tokens, none a near-homophone, each plausible as somebody else; **role context** identified them and the human listening to the audio confirmed them. Such a candidate is now routed to the queue as `kind: entity` for audio verification rather than dismissed *or* rewritten. The sound test keeps full force where it was calibrated (common words the engine handles routinely, per the step-6 rejection heuristics).
- **Phrase-anchoring as the middle path — for the common-word row only (dictionary matrix, doc-only).** The *common word → context word* row forbids a **bare** common word as a rule, not the same fix carried by enough surrounding text that the phrase occurs only in the mishearing. The *real name → different real name* row is **explicitly not relaxed**, and the reason is measured rather than cautionary: `--add`'s jieba check warns when the FROM side decomposes into known words, but personal names are out-of-vocabulary (frequency 0), so a name-anchored rule is judged *not* a known phrase and **emits no warning at all** — verified, `村里商量` and `天空智能` both warn while `<surname><given>商量` warns about nothing. The class with the worst blast radius is the one with no validator feedback, so it stays in the domain context file. Also documents what the validator does and doesn't block: a `valid_phrase` warning is advisory (the rule is added anyway), but `common_word` / `both_common` / `substring_collision` are **errors** — `--add` exits 1 and writes nothing, and `--force` is the only way past, so check the exit status rather than assuming a noisy add succeeded. The worth-adding caveat is unchanged: anchor to a recurring collocation, never a one-off sentence fragment.
- **Upstream-corrected inputs get a raw-diff pass (Native AI Correction step 2, doc-only).** When the transcript already passed through an automated corrector (a sync pipeline's pre-classify stage, a previous Stage 3 API run), the input is no longer raw ASR — upstream corrections are baked in with no evidence trail. The workflow now requires diffing against the raw source before triage, with the two opposite consequences spelled out: every upstream entity swap becomes a suspect (an upstream AI "correction" can be a fluent wrong guess — real case: raw 「新的车辆」 smoothed into 「新出来的反馈」, grammatical and plausible but wrong, caught only by the raw diff), and already-correct fixes are checked *before* being proposed again.
- **Feishu-minute audio wiring recipe for dashboard playback (doc-only).** `lark-cli minutes +download` end-to-end, run from a cache/state directory (its `--output` only accepts a relative path inside the current directory); when lark-cli's SSRF guard refuses Feishu's signed-download host with `blocked download URL: local/internal host is not allowed` (the host's name literally starts with `internal-`), `--url-only` prints a JSON envelope whose `download_url` field `curl` can fetch directly; the file stays outside any docs repo; `ffprobe` duration ≈ the transcript's last timestamp verifies timeline pairing before `Q` playback is trusted.
- **Quick Start notes absolute script paths for cwd-resetting harnesses (doc-only).** The relative `scripts/...` examples fail with `Failed to spawn: scripts/fix_transcription.py` in agent harnesses whose shell resets the working directory between calls; substitute the absolute path (`$CLAUDE_SKILL_DIR/scripts/...`).
- **Native AI Correction: three actionability fixes from real two-transcript use (doc-only).** (1) Step 2 makes the false-positive feedback loop explicit — a Stage 1 false positive is debt you owe the dictionary: disable the bad rule in the same session with `--report-false-positive`, passing the rule's **stored from→to pair** (as `*_changes.md` From/To shows it, NOT "wrong→right" semantics — the `买买→卖卖` FP stored `from=买买, to=卖卖` → pass `"买买" "卖卖"`); one call disables it. (2) Step 5 adds a "common-word batch where most occurrences are the domain term but a few are genuine" pattern: `grep -n` every occurrence, judge each, then `replace_all` + revert the genuine minority (real case: `公开` ×11 — 10 工勘 + 1 real 公开渠道). (3) Step 7 ships a minimal inline `items.json` example (line/original/suggested/context/kind/evidence) + an `actions`-optional note, so `--enqueue-review` no longer requires a jump to references — and it names the two keys the silent-drop rule catches one field over: the verdict is `suggested`, not `suggestion`, and the action pack's key is `actions`, not `action_pack`. Also sweeps `references/dictionary_guide.md`, whose `--report-false-positive` row still taught the "错→对" argument order this entry's item (1) repudiates.
- **Second-pass residual adjudication heuristics + trap-scan (Native AI Correction step 6, doc-only).** The cold subagent's residual list is now explicitly *candidates, not conclusions* (one real run: 10 rows → 4 accepted), with six production-validated accept/reject rules: near-homophone + in-document self-proof accepts; sound-distance falsifies implausible swaps (the sound test now cuts both ways); the **ASR-capability counter-check** (a word the same engine rendered correctly nearby is inside its recognition range, so a different rendering is more likely what was said — a strong prior, not a proof); intelligible real words stay; evidence-free reconstructions die; minimal edit only (never insert unspoken words). New fast-tier **trap-scan**: grep the file for the domain context file's documented trap patterns before (or instead of) a full cold re-read.
- **User-verdict compounding loop (step 4, doc-only).** A user's mid-session resolution of an uncertain item is now treated as the strongest source and cashed in three ways immediately: apply the fix → persist the variant (roster for recurring people, `--add --domain` for project terms) → record it in the ledger/roster/context with verbatim wording, date, and a ✅ user-confirmed marker. Two refinements: collision-check the FROM side against real people in other projects before dict-adding (real-name → real-name fixes go to the domain context as a trap, never the dictionary); confirmed-*correct* entities get a one-line note too, so the next run doesn't re-ask. Dictionary decision matrix gains a "real name → different real name: never a rule" row.
- **`--enqueue-review` item schema documented** (`references/script_parameters.md` §Review Queue Item Schema): full field/alias table (only `original` required), the silent-drop gotcha for unknown keys (`line`, not `line_hint`), temp-dir items skipped entirely, CLI `--domain` fills only items without their own, empty-`suggested` + no-action-pack errors at resolve time, and the five-field dedup key. SKILL.md step 7 cross-references it.
- **Persistent review queue** (`review_items` table): uncertain corrections now have a durable home instead of evaporating. Unifies three previously-lossy flows — native AI-pass uncertain items (were chat-only), Stage 1 safe-mode deferrals (were a `*_needs_review.md` sidecar that temp-dir callers silently discarded; deferrals now auto-enqueue, with temp-dir anchors skipped as dead pointers), and learned-suggestion review. CLI verbs: `--enqueue-review` / `--list-review` / `--show-review` / `--resolve-review ID --decision …`. Each item carries a pre-filled suggestion, evidence, and an optional action pack (`file_edit`/`dict_add`/`append_note`) executed on accept via an in-memory two-phase planner: every action validates against the file state the pack's previous actions produced, and nothing reaches disk unless the whole pack plans clean. Anchor selection is content-first (context snippet outranks a stale line hint), ambiguity fails closed (`re_anchor_needed`, exit 2, machine-readable on stdout), file IO preserves CRLF/LF, and resolve/reopen use conditional-claim UPDATEs so two writers can't silently overwrite each other's verdict. `--json` Stage 1 status gains an additive `review_enqueued` field.
- **Review dashboard** (`scripts/review-dashboard/server.py`, local FastAPI at `127.0.0.1:8767`): Prodigy-style one-keystroke review of the queue — `A` accept / `R` original-is-correct / `W` override / `S` skip / `Z` undo (reopen) / `Q` play the anchored utterance / `↑↓ J K` navigate. Reads the DB read-only; every write shells out to the CLI so the state machine and audit log stay the single source of truth. Audio playback is opt-in per transcript via an explicit frontmatter `audio:` field (unquoted, `~`-expanded, relative paths resolved against the transcript's directory, `is_file()` gated — no ghost buttons) with the clip window derived from surrounding speaker timestamps and served with HTTP Range. Env: `REVIEW_DASHBOARD_PORT`, `REVIEW_DASHBOARD_NO_BROWSER`. Hardened by a status×feature test matrix plus adversarial-probe regressions (38 tests in `test_review_queue.py` + `test_dashboard_context.py`): decided items keep context/audio by anchoring on the resolved text, stale context responses can't bind audio to the wrong card, background refresh never repaints while typing or listening.
- **Domain correction contexts (per-domain AI priors).** New convention: one markdown file per domain at `~/.transcript-fixer/contexts/<domain>.md` (user space, survives skill updates), read by the native AI-correction workflow before triage. It carries the third error class that fits neither the dictionary nor the people roster: **context-dependent homophones** (e.g. `减`→`剪` only when the discussion is about producing N video clips) — as *cues that prime judgment*, never as hard replacement rules. SKILL.md documents the convention (new "Domain Correction Contexts" section, workflow step 3, dictionary decision matrix now routes common-word homophones here); format + worked template in `references/domain_context_guide.md`. Native-only for now: API mode (`--stage 2/3`, backup channel) does not inject contexts yet.

- **`fetch_minute_audio.py` could exit 3 ("nothing usable produced") with a perfectly good file on disk.** The `--transcript` existence check ran after the download, so a typo'd transcript path reported the failure mode whose documented cause is a wrong `--profile`. Input validation now runs before any network work — verified that the failing case leaves no file behind. Also fixed in the same pass: the all-zero-timestamps branch returned early and skipped the bare-value warning that accompanies the `audio:` line everywhere else; SKILL.md's exit-2 row omitted that case (the script's docstring already covered `ffprobe` failing, the doc did not); an `ffprobe` that ran but emitted something unparseable reported "ffprobe unavailable", sending the operator to install a tool that had just executed; and an unreadable transcript or an un-writable `--output` directory raised uncaught `OSError`s that surfaced as exit 1 — the code reserved for a real timeline mismatch. All six exit paths recalibrated end to end.
- **The override fix's file-writing symptom now has its own regression test.** The first pass only covered the `dict_add` half; `test_override_retargets_file_edit_when_item_has_no_file_anchor` covers the worse half (the rejected suggestion being written into the transcript) and fails against the pre-fix gate.
- **Step 6's cross-language carve-out no longer states a weaker condition than step 4's.** The carve-out had been reworded to a single question (is this a cross-language proper noun?) while step 4 requires *both* that and the candidate sitting in a known person's slot — so step 6 would have routed strictly more candidates to the queue than step 4 defines. Now states both conditions. (The reword did fix a genuine self-contradiction in the previous text, which claimed the rejection rule still governs "every residual whose sound distance is the whole objection" — true of nothing inside the carve-out.)
- **The `find` fallback's guidance no longer quotes a count that goes stale every release, and covers unversioned installs.** Each release adds two hits, so the printed number drifted within the same day; and after the documented skip list, marketplace checkouts and other agents' skills directories survive with no version component at all, leaving "take the highest version" undefined for exactly the copies most likely to be picked.
- **The by-hand fallback's URL extraction was more brittle than the script it substitutes for.** It piped `--url-only` straight into `json.load(sys.stdin)`, while the script deliberately isolates the JSON object because the CLI may print prose around it (`raw.find("{")` … `raw.rfind("}")`). Reproduced: prose before the JSON made the one-liner exit 1 with an empty `URL`, and the following `curl` ran anyway. The block now mirrors the script's isolation and checks that `URL` is non-empty.
- **An override could write the answer the human REJECTED into the dictionary.** `resolve(..., "overridden")` retargets file edits to the human's text and drops suggestion-specific actions (`dict_add` / `append_note`) — but the whole block was gated on `item.file_path`, and `file` is optional in the enqueue schema. An anchor-less item carrying a `dict_add` therefore skipped the block entirely and executed it with the **rejected** `suggested_text`, printing `✓ dictionary rule added` as if it had succeeded — and a dictionary rule then auto-applies that rejected answer to every future transcript in the domain. Reproduced against an isolated DB: human typed `HumanTruth`, dictionary got `WrongGuess`. The drop is now unconditional; the human's text stays in `resolved_text` for a deliberate `--add`. Regression test: `test_override_skips_dict_add_when_item_has_no_file_anchor`.
- **`fetch_minute_audio.py` reported operational failures as timeline mismatches.** Every hard failure — lark-cli erroring, an unparseable envelope, **a `--profile` that cannot read the minute**, curl failing, a too-small download — exited 1, the code documented as "timeline mismatch, do not wire this file". An operator following that reading goes hunting for a different recording when the actual fix is a different profile. Those now exit **3** (nothing usable downloaded); 1 means a real file whose timeline disagrees. Also fixed: a missing `--transcript` path raised an uncaught `FileNotFoundError` (also surfacing as 1) and now exits 3, and a transcript whose speaker timestamps are all `00:00:00` used to skip the comparison and print "pairing looks correct" with exit 0 — a false verified — and now exits 2. Calibrated across all six paths.
- **The `audio:` frontmatter example silently disabled the feature it documented.** The example carried an inline `#` comment, and the dashboard's parser takes everything after the first colon without stripping comments — so a literally-copied line yields a path ending in the comment text, which does not exist, and the card renders with **no play button and no error**, reading exactly like "this transcript has no audio." The example is now a bare value in a complete frontmatter block, with the constraint spelled out (and the same warning printed by `fetch_minute_audio.py` when it emits the line).
- **The documented remedy for cwd-resetting harnesses did not work.** Prerequisites told the reader to substitute `$CLAUDE_SKILL_DIR/…`; that variable is UNSET in at least one real agent harness (verified 2026-08), so the cure produced the exact `Failed to spawn: scripts/fix_transcription.py` error it was meant to prevent — on the first command of the skill. Now points at the "Base directory for this skill" line the harness prints at invocation, with a `find -L` fallback, and warns off the env var.
- **Step 6's sound-distance rejection contradicted step 4's new cross-language exception.** Both rules addressed the same residual and pointed opposite ways (enqueue for audio verification vs. reject on implausible sound), leaving the adjudication unresolvable. Step 6 now carves out that one class explicitly and reaffirms the rule for everything else.
- **Real colleagues' names removed from the public examples (privacy).** The people-roster format example and the roster-lookup example named three real individuals with their real ASR variants — one of the variants having been lifted verbatim from an actual recording — and the dictionary matrix's "real name → different real name" row named two more. In a public repo (1300+ stars, 200+ forks) these were third-party PII sitting in illustrations, the exact blind spot the skill's own sanitization guidance calls out: a keyword scanner cannot see a CJK name, so a green security scan never flagged them across releases. Replaced with invented equivalents that preserve every teaching point — the roster example still shows that an English given name spoken inside Chinese speech yields both a misspelling and a transliteration, and the matrix still shows two near-homophone real names colliding.
- **The 0-correction domain hint no longer claims a loaded domain is empty.** With `--domain X` and zero matches, the hint printed "no rules in domain 'X'" even when X's rules loaded fine but simply did not match this transcript — sending operators investigating why their loaded domain was "empty" (the two realities call for opposite responses: clean transcript vs typo'd domain). The message now distinguishes "0 of N rules in domain 'X' matched this transcript" from a truly rule-less domain, and the "run without --domain" total counts all rules instead of excluding the requested domain. Extracted as the pure `_format_domain_hint`; regression tests in `scripts/tests/test_domain_hint.py`.
- **`--apply-all` no longer gets hijacked by a stale `_stage1.md`.** The auto-finalize promote guard ran before corrections for any stage-1 invocation: if a previous safe-mode run had left `_stage1.md` behind (possibly with ZERO corrections applied — safe mode defers medium/high rules), an explicit `--apply-all` promoted that stale sidecar, printed "Finalize complete", and exited — the requested correction run never happened and the ASR errors stayed in the file (observed 2026-07-10: 13 high-risk name fixes silently skipped on a real meeting transcript). `--apply-all` now skips the promote path and always runs corrections from the input as-is; finalize remains the job of a plain `--stage 1` re-run. Regression test: `scripts/tests/test_stage1_auto_finalize.py::test_cmd_apply_all_ignores_stale_stage1_and_runs_corrections`.
- **Stage 3's diff report no longer reads a `_stage1.md` this run didn't produce.** On a 0-correction run `_stage1.md` is skipped (see below), but the Stage 3 report still passed that path to `generate_full_report`: with no leftover file the report failed with a swallowed `FileNotFoundError`; with a stale leftover from a previous run it silently mixed old content into the diff. The report now reads the input file as the stage-1 column whenever this run applied 0 corrections (byte-identical by definition).
- **Native/stage-1 runs no longer nag about a missing API key.** `get_config()` logged `Configuration warnings: ['API key not set (required for AI corrections)']` on every command, including the default native workflow that never touches the API (the key has been unset for 8.5 months of daily native use). The warning is now gated behind `Config.validate(include_api_key_warning=...)`: suppressed at generic config load, still surfaced by the explicit `--validate` health check, and `--stage 2/3` keeps its own fail-fast error.
- **`--output FILE.md` no longer creates a directory of that name (false-success footgun).** `--output` was always treated as a directory: passing a file path (e.g. `--output result.md`) silently ran `mkdir result.md/` and wrote `<stem>_stage1.md` inside it, while the console printed only a basename (`Saved: <stem>_stage1.md`) — the run looked successful but the file was not where it was asked for. A `--output` whose suffix is `.md`/`.markdown`/`.txt` and is not an existing directory is now written directly to that exact path (directory `--output` unchanged, backward-compatible). Every `Saved` / changes-report / needs-review / dry-run / stage-2 line now prints the **full resolved path** instead of a bare basename, so a misdirected output is immediately visible.
- **`--add` on a soft-deleted rule no longer crashes with a misleading "Correction not found".** When `(from_text, domain)` already existed but was disabled (`is_active=0`, e.g. previously reported as a false positive via `--report-false-positive`), the UNIQUE-conflict handler updated only `is_active=1` rows, matched nothing, and raised `Correction not found` — a crash, not a message. `add_correction` now queries the existing row regardless of `is_active` and upserts deliberately: an active row is updated in place; a disabled row is **not** silently resurrected — without `--force` it reports the disable reason/date + old target and instructs to re-run with `--force`, and with `--force` it reactivates and updates the target, logging a `reactivate_correction` audit entry. `force` is threaded CLI → service → repository. Documented in `references/false_positive_guide.md` (§Re-adding a disabled rule).

### Changed
- **Stage 1 re-runs now auto-finalize**: if `*_stage1.md` exists and is newer than the input file, running `--stage 1` again atomically promotes it to the input filename and removes intermediate sidecars (`_stage2.md`, `_dryrun.md`, `_changes.md`, `_needs_review.md`, `_uncertain.md`, `_对比.html`). It skips promotion when the input file is newer, so manual edits are never overwritten. This removes the need for a separate manual finalize command in the native AI-correction workflow.
- **Stage 1 no-op runs write no sidecars.** When a `--stage 1` run applies 0 corrections (clean transcript, or a native re-run after the input was already edited), it no longer writes `_stage1.md` (a byte-copy of the input); when nothing was deferred either, `_changes.md` ("No corrections applied") is skipped too. Both were pure noise: they never auto-finalized (the promote guard skips when the input is newer — exactly the native case) and forced a manual `rm`. When safe mode does defer medium/high rules, `_changes.md` and `_needs_review.md` still write — they are the deferral report, so human review is never lost. Regression test in `scripts/tests/test_stage1_auto_finalize.py::test_cmd_stage1_zero_corrections_writes_no_sidecars`.
- Auto-finalize promotion uses `os.replace` with a `shutil.copy2` fallback so it works even when the input file and sidecars live on different filesystems.
- Learned-suggestion review is now wired end-to-end: `--review-learned` analyzes SQLite `correction_history` / `correction_changes`, merges high-confidence repeated patterns into `~/.transcript-fixer/learned/pending_review.json` without duplicates, and `--approve FROM TO` adds the exact suggestion to the dictionary as `source='learned'` before removing all matching pending rows.
- Correction dictionary import/export is now exposed in the CLI: `--export PATH` writes a metadata-wrapped JSON export for the selected `--domain`, and `--import PATH [--merge]` reads both the current wrapped format and legacy plain `{from: to}` JSON dictionaries.
- **Stage 1 now defaults to "safe mode"**: only low-risk (non-word, high-confidence) corrections are auto-applied. Medium/high-risk ones (common words, ≤2-char, real-word fragments) are tracked to `*_needs_review.md` for human/AI review instead of being applied silently. `Applied: 0` on a clean transcript is now expected, not a bug. Pass `--apply-all` to restore the previous apply-every-level behavior.
- Expanded `utils/common_words.py` with real common words that had been mis-added as correction sources (`多深`, `早生`, `龙虾`, `小龙虾`), so the add-time guard, the risk classifier, and `--audit` all recognize them.
- Context rules are now gated by `review_mode` like dictionary rules (safe mode defers risky ones instead of applying them unconditionally).
- `--audit` runs an advisory jieba heuristic to surface 4+ char "real-word" false-positive rules for human review (see Known limitations). Adds `jieba` to dependencies.
- **Finalize now prescribes `/bin/mv -f` instead of a bare `mv`.** SKILL.md step 9 and new troubleshooting entry #7: on macOS `mv` is commonly aliased to `mv -i`, which skips overwriting an existing target while still exiting 0 — so a finalize `mv *_stage1.md *.md && echo done` reported success while the un-corrected file silently survived as the output. Doc-only change.
- **Native AI Correction step-4 ("Needs verification") now prescribes a local-first search ladder.** Previously the instruction was "Search it, don't guess — WebSearch, or a local grep," which put WebSearch first and left "local grep" vague — so project / person names whose canonical spelling already lived in another `corrections.db` domain or in project delivery docs got escalated to the user instead of resolved locally. The ladder now orders: all `corrections.db` domains (not just the current `--domain`) → project delivery docs → memory → WebSearch (public entities only) → then the user. Doc-only.

### Deprecated
- `--review` is now a no-op (safe mode is the default). Use `--apply-all` for the opposite behavior.

### Fixed
- **False-positive class where the risk guard was computed but then ignored.** `_assess_risk()` already classified risky rules correctly (`多深`→high, `小龙虾`→medium), but `review_mode` defaulted to `False`, so every risk level was applied regardless. On a clean Feishu-ASR transcript this silently corrupted correct text (`抓多深`→`抓多申`, `小龙虾`→`小 Claude`). Safe-mode-by-default now defers all medium/high-risk changes — dictionary **and** context rules. This narrows the class but does NOT fully close it (see Known limitations). Regression tests in `tests/test_common_words_safety.py::TestProductionFalsePositives2026_06`.
- **`_apply_context_rules` now honors `review_mode`.** Previously context (regex) rules were applied unconditionally even in safe mode, and the run summary mis-counted them as "skipped" while the text was already mutated. They are now risk-gated like dictionary rules, so the summary and `*_needs_review.md` are accurate.
- **`fix_transcript_enhanced.py` no longer silently flips to safe mode.** Its hand-built args now pass `apply_all=True`, preserving this automation entry point's historical "apply everything" behavior (the safe-mode default had silently downgraded it with no opt-out).
- **History no longer records non-applied changes.** In safe mode, skipped medium/high Stage-1 changes were persisted to the history table as if applied; only actually-applied changes are now recorded.
- **Fixed SQLite connection pool thread-safety bug.** `ConnectionPool` was creating connections with `check_same_thread=True`, then handing them to worker threads via a queue. SQLite forbids using a connection outside its creation thread, so concurrent tests failed with "SQLite objects created in a thread can only be used in that same thread." Switched to `check_same_thread=False` (safe because the queue enforces one-thread-at-a-time exclusive access).
- **Fixed test suite import and dependency issues.** Added missing `sys.path` setup to `scripts/tests/test_connection_pool.py`, made `test_apply_all_applies_real_word_phrase` skip when `jieba` is unavailable, and added `pytest` / `pytest-asyncio` to `requirements.txt` so the existing async/error-recovery tests can run.

### Known limitations
- **Safe mode does NOT catch the "4+ char real-word" false-positive class.** `_assess_risk` labels any rule with `len(from_text) >= 4`, confidence ≥ 0.9, and not in the common-word list as `low`, so it auto-applies — even when `from_text` is itself valid text (`济南大学`→`暨南大学`, `关税证明`→`完税证明`). This is structural: "low risk" is defined by length/confidence/word-list, which is orthogonal to "is this real text." `--audit` now uses a jieba heuristic (`is_likely_valid_phrase`) to **surface** such rules for human review, but it is advisory and low-precision (it also flags many legitimate ASR-garble rules, not just genuine false positives), so it cannot gate auto-application. Fully closing this class needs language-model-grade validity judgment, not a dictionary heuristic.
